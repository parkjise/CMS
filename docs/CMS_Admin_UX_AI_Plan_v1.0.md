## 1. 화면 개선

### U-1 나가기 확인 창 (T-227)

- **지금:** `useLeaveGuard` 가 브라우저 기본 `window.confirm`("저장하지 않은 변경사항이 있습니다…")을 띄운다. 저장하려면 [취소] → 저장 버튼을 다시 찾아야 한다.
- **바꿀 것:** 관리자 공통 모달 하나로 바꾼다.
  - [저장하고 이동] — 그 화면의 저장을 실행하고, 성공하면 이동. 실패하면 모달을 닫고 화면에 남아 오류 알림(입력은 그대로).
  - [저장하지 않고 이동] — 바뀐 내용을 버리고 이동.
  - [계속 편집] — 닫기 (Escape · 바깥 클릭도 같음).
  - 저장을 막는 값이 있으면(글자 수 초과 등) [저장하고 이동]을 끄고 까닭을 보여 준다.
- **쓰는 곳:** 사이트 관리 6개 화면 · SEO · 게시판 설정(U-2) · 게시판 디자인.
- **창 닫기 · 새로고침:** 브라우저가 직접 묻는 확인(`beforeunload`)은 바꿀 수 없어 그대로 둔다.
- **구현 (T-227 ✅):** 훅 대신 컴포넌트 `<LeaveGuard dirty onSave saveBlockedReason message />` (`components/site/LeaveGuard.tsx`) — 확인 창을 그려야 해서. `onSave` 는 성공 여부(`Promise<boolean>`)를 돌려준다. 없으면 두 가지 선택지(게시판 만들기). 예전 `useLeaveGuard` 는 지웠다.

### U-2 게시판 설정 한 번에 저장 (T-228)

- **지금:** 설정 화면(`/admin/boards/:id/settings`)의 기본 정보 · 권한 · 운영 설정 · 홈페이지 연결 구역마다 [저장]이 있다. 메뉴 위치는 고르면 바로 저장된다. 다른 구역에서 고친 내용은 경고 없이 사라질 수 있다.
- **바꿀 것:**
  - 구역별 [저장]을 없애고 사이트 관리와 같은 **아래 고정 저장 막대** 하나. 메뉴 위치도 막대로 저장한다.
  - 고친 구역 제목 옆에 `수정됨` 점, 구역 바로가기 칩에도 같은 점.
  - 나가기 확인(U-1).
- **서버:** 바꿀 필요 없다. 네 구역 모두 같은 `PATCH /api/v1/boards/{id}` 에 일부 값만 보내므로, 바뀐 구역의 값을 합쳐 **요청 한 번**으로 보낸다 (한 트랜잭션 — 일부만 저장되는 일이 없다). 오류의 `field` 로 해당 구역을 펼치고 그 칸에 표시한다.
- **영향 안내 (QA 2.2-3):** 저장 막대 위에 바뀐 값의 결과를 한 줄씩:
  - 읽기 `누구나 → 회원만` · 검색 노출 끔 → "검색엔진 사이트맵에서 빠집니다", AEO 에 연결된 FAQ 게시판이면 "FAQ 구조화 데이터도 빠집니다".
  - 사용 안 함 → "홈페이지 메뉴 · 사이트맵에서 빠집니다".
  - 주소(slug) 변경 → "예전 주소로 들어온 방문자는 찾지 못합니다".
- **복제 · 휴지통** 버튼은 저장과 별개라 그대로 둔다 (저장 안 한 내용이 있으면 먼저 U-1 확인).
- **구현 메모 (T-228 ✅):** '상단 메뉴에 표시'는 게시판이 아니라 사이트 메뉴 설정(`PUT /site-settings/menu`)이라 한 요청에 묶을 수 없어 바로 적용으로 두고 안내했다. 영구 삭제 수는 지금 응답에 없어 `GET /boards/{id}/purge-preview` 를 더했다 (DB 변경 없음).
- **U-8 영구 삭제 확인:** 휴지통의 게시판 [영구 삭제]를 `window.confirm` 대신 모달로 — 지워질 글 · 필드 · 카테고리 · 첨부 수를 보여 주고, 게시판 이름을 똑같이 입력해야 [영구 삭제]가 켜진다. 글 영구 삭제는 지금처럼 확인 창 하나.

### U-3 게시판 관리 메뉴 정리 (T-229 ✅ — 2026-11-23 사용자가 6개안 선택)

- **지금 (T-187, 2026-11-11 결정):** 하위 메뉴 11개 — 게시판 목록 / 게시판 만들기 / 게시판 디자인 / 필드 관리 / 게시글 관리 / 카테고리 관리 / 권한 관리 / 휴지통 / 환경설정 / 신고된 글 / 변경 기록. 디자인 · 필드 · 카테고리 · 권한 · 환경설정은 '마지막으로 작업한 게시판'을 연다.
- **문제 (QA):** 필드 · 카테고리, 권한 · 환경설정이 같은 화면으로 간다 (T-212 에서 화면을 합친 뒤). 어느 게시판이 열릴지 메뉴만 보고는 알 수 없다.
- **제안 (추천):** 하위 메뉴 6개.

  ```text
  게시판 관리
  ├── 게시판 목록      /admin/boards           (+ 오른쪽 위 [게시판 만들기])
  ├── 게시글 관리      /admin/posts
  ├── 신고된 글        /admin/posts/reports    (처리 안 한 신고 수 배지)
  ├── 휴지통           /admin/boards/trash
  ├── 변경 기록        /admin/boards/history
  └── 게시판 만들기    /admin/boards/new       ← QA 는 목록 버튼으로만 두자고 했지만, 자주 쓰는 첫 작업이라 남김
  ```

  - 게시판별 화면(글 관리 · 필드 · 카테고리 · 디자인 · 설정)은 **게시판 목록 → 게시판 → 탭**으로만 들어간다. 탭 위의 '작업 중인 게시판' 고르기로 다른 게시판으로 바로 옮긴다 (지금도 있음).
  - 예전 주소(`/admin/boards/design` 등)는 지금처럼 마지막으로 작업한 게시판의 그 화면으로 보낸다 — 즐겨찾기 · 도움말 링크가 깨지지 않게.
  - 게시판 목록 행의 [설정] 옆에 [디자인] 바로가기를 더한다.
- **QA 안(5개)과 다른 점:** [게시판 만들기]를 메뉴에 남긴다. 빼고 싶으면 확인 때 말해 주면 된다.
- **확인할 것:** T-187 에서 사용자가 고른 11개 메뉴를 다시 줄이는 결정이다. 이 태스크는 확인을 받은 뒤 시작한다.

## 2. AI 보조 기능

### 2.0 공통 규칙 (모든 A-항목)

- **화면 먼저 (2026-11-23 사용자 결정):** 서버보다 화면을 먼저 만든다. 각 기능을 화면(T-23x-A)과 서버(T-23x-B)로 나눈다.
  - 화면은 실제 코드로 만들되 기능 스위치가 켜진 사업체에만 보인다. 스위치는 서버 태스크에서 만들어 시드에 넣으므로, 그전에는 어떤 고객에게도 버튼이 보이지 않는다 — '준비 중' 버튼을 두지 않는 원칙(게시판 기획서 4장) 그대로.
  - 개발 서버에서 주소에 `?ai-preview` 를 붙이면 이 탭 동안 스위치 없이 버튼이 보이고, 서버 대신 예시 결과(`lib/aiAssistPreview.ts`)로 눌러 본다. 운영 빌드(`import.meta.env.DEV` 거짓)에서는 늘 꺼진다.
  - 화면이 보내는 요청 · 받는 응답은 아래 서버 규칙의 모양 그대로 — `POST /api/v1/ai/assist/{kind}` `{tone, …}` → `{result, usage: {used, limit, remaining}}`. 서버를 붙여도 화면은 그대로다.

- **사람이 마지막에 정한다:** AI 결과는 폼에 채우거나 미리보기로만 보여 주고, 저장 · 공개는 늘 관리자가 누른다. 자동 저장 · 자동 공개 · 자동 조치 없음.
- **보내는 정보:** 사업체가 직접 입력한 사이트 정보 · 설정값 · 관리자가 쓴 메모만 보낸다. **방문자가 쓴 글 · 이름 · 연락처는 보내지 않는다** (그래서 A-7 을 미룸).
- **기능 플래그 · 요금제:** 기능마다 플래그를 따로 둔다 — 슈퍼 어드민이 하나씩 끌 수 있게. 사용 한도는 기존 'AI 문구 추천' 월 한도(FREE 5 · BASIC 20 · STANDARD 100 · PREMIUM 무제한)를 함께 쓴다 — 한도가 늘어나 요금이 새지 않게.

  | 플래그 | 기능 | 요금제 |
  |---|---|---|
  | `AI_SITE_ASSIST` | A-1 SEO · GEO 자동 채우기, A-4 약관 변경 요약 | 전 요금제 (문구 추천 한도) |
  | `AI_BOARD_ASSIST` | A-2 게시판 구성 추천, A-3 글 초안 | 전 요금제 (문구 추천 한도) |

  새 플래그는 시드(`scripts/seed.py`)와 슈퍼 어드민 기능 목록에 더하고, 메뉴는 없다 (버튼만 숨김).
- **서버:** `POST /api/v1/ai/assist/{kind}` 하나로 받는다. `kind` 마다 입력 스키마 · 프롬프트 · **결과 스키마**를 정하고, 모델 답을 결과 스키마로 검증해 맞지 않으면 한 번 다시 묻고 그래도 안 되면 502 "AI 가 알맞은 답을 주지 못했어요". 결과의 글자 수 · 개수 제한은 저장 API 와 같은 규칙으로 잘라서 돌려준다.
- **기존 것 재사용:** 분당 호출 제한(`ai_rate_limit_per_minute`), 같은 입력 1시간 캐시, `ai_usage_log`(`action_type = assist_{kind}`), 키가 없거나 장애면 502 안내 (T-078 시나리오 6 과 같게).
- **화면:** 버튼은 `✨` 아이콘 + 동사 ("AI 로 채우기"). 결과는 오른쪽 서랍(모바일은 아래 시트)에 미리보기 → [적용] / [다시 만들기] / [닫기]. 남은 사용 횟수를 서랍 아래에 보여 준다. 보기 전용 계정은 버튼을 숨긴다.
- **문구:** "AI 가 만든 초안이에요. 사실과 다른 내용이 없는지 확인해 주세요."를 늘 보여 준다.

### A-1 SEO · GEO 문구 자동 채우기 (화면 T-231-A ✅ · 서버 T-231-B, 1순위)

- **위치:** SEO 설정 '기본 SEO' 탭 위, GEO 설정 '기업 · 브랜드 정보' 카드 오른쪽 위 — [✨ 사이트 정보로 채우기].
- **입력 (서버가 직접 읽음):** 사이트 기본정보(사이트명 · 회사명 · 업태 · 종목 · 주소의 시 · 구까지 · 운영시간 요약), 업종, 지금 SEO · GEO 값, 공개 중인 섹션 제목. 관리자는 말투(신뢰감 · 친근함 · 전문적)만 고른다.
- **결과:** SEO — 메타 제목(60자 안) · 메타 설명(160자 안) · 대표 키워드 5개. GEO — 기업 소개(500자 안) · 주제 키워드(10개, 각 30자).
- **적용:** 항목마다 체크박스로 골라 [고른 N개 적용] → 폼에 채워지고 저장 막대가 켜진다 (저장은 관리자가). 지금 값이 있는 칸은 기본 체크 해제하고 '지금: …'을 함께 보인다. 키워드는 요금제 한도, GEO 주제는 10개로 자른다. 키워드를 못 쓰는 요금제는 키워드 칸을 빼고 만든다.
- **화면 구현 (T-231-A ✅):** `components/ai/AiDrawer.tsx`(공통 서랍) · `AiFillAssist.tsx`(채우기 버튼 + 결과), `hooks/useAiAssist.ts`. 실패는 서버 메시지 그대로(한도 초과 · 502), 없으면 'AI 가 알맞은 답을 주지 못했어요'.
- **사실 확인:** 사이트 정보에 없는 수치 · 수상 · 자격은 쓰지 말라고 프롬프트에 넣고, 결과에 숫자가 있으면 "숫자가 사실인지 확인해 주세요" 표시.

### A-2 게시판 구성 추천 (화면 T-232-A ✅ · 서버 T-232-B)

- **위치:** 게시판 만들기 1단계 위 [✨ AI 로 구성 추천받기], 필드 · 카테고리 화면 위 [✨ 필드 · 카테고리 추천].
- **입력:** 관리자가 쓴 목적 한두 문장(200자), 업종, 이미 있는 게시판 이름.
- **결과 (서버가 검증):** 유형(그 사업체가 고를 수 있는 유형만 — `type-options` 의 막힌 유형 제외, 병원 업종 리뷰형 불가), 이름 · 설명, 추가 필드(최대 8개, 기존 필드 유형만), 카테고리(최대 10개), 권한 · 운영 추천값과 까닭 한 줄.
- **적용:** 만들기 마법사는 2 ~ 4단계 값을 채우고 5단계(검토)로 바로 간다. 권한 · 운영도 4단계 값으로 채우고 까닭 한 줄과 "만든 뒤 설정에서 바꿀 수 있어요"를 함께 보인다 (만들기 전 검토에서 고칠 수 있음). 필드 화면은 추천 필드 · 카테고리를 골라 [추가] — 이름이 같은 필드 · 카테고리는 건너뛴다.
- **요청 · 결과 모양 (T-232-A):** `POST /ai/assist/board` `{purpose, board_id?}` — `board_id` 가 있으면 그 게시판에 더할 필드 · 카테고리 추천. 결과 `{board_type, name, description, fields: [{label, field_type, choices}], categories: [], permissions, operation, reason}`. 말투는 받지 않는다.
- **화면 구현 (T-232-A ✅):** `components/ai/BoardSuggestAssist.tsx`. 항목마다 골라 적용 — 지금 이름이 있으면 이름 · 설명은 처음엔 고르지 않음, 고를 수 없는 유형은 유형을 그대로 두고 알림, 회원 권한이 막힌 사업체는 그 칸을 처음 값으로. 추천 필드 · 카테고리는 게시판을 만든 뒤 차례로 만든다(`hooks/useBoardSuggestion.ts`) — 기본 필드 · 함께 만들 추천 칸과 이름이 같으면 건너뛰고(띄어쓰기 · 대소문자 무시), 일부 실패해도 게시판은 남기고 실패 수를 알린다.
- **안전:** 후기 게시판에 비회원 쓰기 같은 위험한 조합을 추천하면 서버가 기본값으로 바꾸고 까닭을 붙인다.

### A-3 공지 · FAQ 글 초안 (화면 T-233-A ✅ · 서버 T-233-B)

- **위치:** 글쓰기 편집기 툴바 [✨ AI 초안]. AEO 화면의 [질문 추가] 옆에도 [✨ 질문 초안] (FAQ 게시판 글쓰기로 이동하며 초안 서랍을 연다).
- **입력:** 메모(500자, 예: "추석 연휴 9/14~9/18 휴진, 응급은 카카오 채널"), 게시판 유형, 사업체 이름 · 연락처(사이트 기본정보에서).
- **결과:** 제목 후보 3개 + 본문(문단 · 목록만). FAQ 게시판이면 질문 · 답변 한 쌍.
- **적용:** 고른 제목은 제목 칸에, 본문은 편집기 노드 JSON(문단 · 글머리 목록)으로 바꿔 넣는다 (HTML 을 그대로 넣지 않는다 — T-143 저장 규칙). 글이 비어 있지 않으면 "지금 본문 뒤에 붙일까요, 바꿀까요?" — 붙이기는 본문 끝에 (T-233-A 결정), 그대로 두기도 고를 수 있다.
- **요청 · 결과 모양 (T-233-A):** `POST /ai/assist/post` `{memo, board_id}` — 게시판 유형 · 사업체 이름 · 연락처는 서버가 읽는다. 결과 `{titles: [], body: [{type: 'p', text} | {type: 'ul', items}]}`, FAQ 게시판이면 `titles` 는 질문 하나 · `body` 는 답변. 말투는 받지 않는다.
- **화면 구현 (T-233-A ✅):** `components/ai/PostDraftAssist.tsx`, `lib/aiPostDraft.ts`. 지금 제목이 있으면 처음엔 제목을 그대로 두고, 넣은 본문은 실행 취소로 되돌린다. 숫자가 있으면 확인 안내. AEO [✨ 질문 초안] 은 글쓰기 주소에 `?ai-draft` 를 붙여 서랍을 연다.
- **번역(A-6)은 하지 않는다:** 홈페이지에 언어 전환이 없어, 번역 글은 같은 게시판에 섞여 보일 뿐이다. 다국어 홈페이지를 기획할 때 함께.

### A-4 약관 변경 내용 요약 (화면 T-234-A · 서버 T-234-B)

- **위치:** 약관 편집의 '변경 내용 요약' 칸 옆 [✨ 바뀐 곳으로 요약].
- **입력:** 지금 공개본(없으면 기본 문안)과 편집 중인 초안 — 서버가 줄 단위로 비교해 **바뀐 줄만** 보낸다 (전체 약관을 보내지 않음).
- **결과:** 1 ~ 3줄 요약(500자 안). 칸에 채우고 관리자가 고쳐 저장.
- **바뀐 곳 보기:** 같은 비교 결과를 화면에 보여 준다 (U-5).
- **경고:** "법적 효력이 있는 문서예요. 요약이 실제 변경과 맞는지 확인해 주세요."

### 미룬 것

- **A-5 업종 맞춤 약관 문안:** AI 가 만든 법률 문서를 그대로 쓰게 되면 책임 문제가 크다. 오픈 전 법률 확인(메모리 · TASK 사용자 할 일)에서 업종별 기본 문안을 정한 뒤, 그 문안 안에서 사업자 정보를 바꿔 넣는 기능으로 다시 본다.
- **A-6 다국어 번역:** A-3 참고.
- **A-7 신고 글 AI 분석:** 방문자가 쓴 글(개인정보가 들어 있을 수 있음)을 해외 AI 서비스로 보내려면 개인정보처리방침의 국외 이전 고지가 필요하다. 법률 확인 뒤, 사업체가 켤 때만 쓰는 선택 기능으로 다시 기획한다. 그때도 자동 조치는 하지 않고 배지만.

## 3. 순서와 의존 관계

> AI 는 화면(-A)을 먼저 모두 만들고, 서버(-B)는 T-231-B 부터 (2026-11-23 결정). 아래 그림의 AI 줄은 서버 순서다.

```text
T-227 나가기 확인 창 ──┬─▶ T-228 게시판 설정 한 번에 저장 · 영구 삭제 확인
                        └─▶ T-230 사이트 관리 작은 개선 (약관 새 버전이 U-1 을 씀)
T-229 게시판 메뉴 정리        ← 사용자 확인 뒤
T-231 AI 공통 + SEO · GEO 채우기 ─▶ T-232 게시판 구성 추천 ─▶ T-233 글 초안
                                  └─▶ T-234 약관 변경 요약 (T-230 의 비교 사용)
```

- 화면 개선(T-227 ~ T-230)과 AI(T-231 ~ T-234)는 따로 진행할 수 있다.
- AI 는 T-231 이 공통 엔드포인트 · 서랍 · 플래그를 만든다 — 나머지는 그 위에 `kind` 만 더한다.

## 4. 머지 전 확인 대상 (CLAUDE.md 12.8)

- DB 변경 없음.
- T-229 는 메뉴 정책 변경이라 시작 전 확인.
- T-231-B 는 새 기능 플래그 · 외부 AI 호출이 늘어 요금에 영향 — 머지 전 확인. 화면 태스크(-A)는 스위치가 없어 고객에게 안 보이므로 CI 통과 시 머지.
- 나머지는 CI 통과 시 머지.
