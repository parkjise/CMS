## 0. 현재 시스템 기준 (반드시 먼저 읽기)

| 항목 | 지금 상태 | 이 기획에서의 처리 |
|---|---|---|
| 사이트 | 사업체(테넌트) 하나 = 사이트 하나. 모든 표에 `tenant_id` + RLS | `site_id` 개념 없음. 사이트 필터 제거 |
| 페이지 | 섹션의 `page_key`(기본 `home`)로 구분. 코드형 템플릿은 매니페스트 `pages` 가 페이지 목록을 정함 (기획서 11.9). 테마형은 한 페이지(메뉴 = 홈 섹션 이동) | `pages` 표를 추가해 **템플릿 기본 페이지 + 직접 만든 페이지**를 함께 관리 |
| 주소 | `/{slug}` 홈, `/{slug}/{page_key}`, 게시판 `/{slug}/b/{게시판}/{글}`, 공지 `/{slug}/notice/{글}` | 직접 만든 페이지도 `/{slug}/{page_key}` **한 단계**만. 상위 페이지는 메뉴 묶음용 |
| 예약 주소 | `preview` · `login` · `sitemap.xml` · `member` · `paused` · `b` · `notice` · `terms` · `privacy` + 템플릿 페이지 키 | 페이지 주소로 쓸 수 없음 (서버에서 검사) |
| 편집 | 관리자 섹션 편집(`/admin/content`) + 홈페이지 인라인 편집 모드. **저장 즉시 공개** | MVP 는 즉시 공개 유지. 초안/발행 분리는 별도 단계 |
| 메뉴 | 사이트 관리 > 메뉴(`/admin/site/menu`, `site_settings.menu_items`) | 새 페이지가 메뉴 선택지에 자동으로 나타남 |
| SEO | 사이트 전체 하나(`seo_settings`) | 페이지별 제목·설명·OG 이미지·검색 제외 추가 (비면 사이트 값) |
| 반복 콘텐츠 | 게시판 모듈(사용자 정의 필드·분류·휴지통·이력) | FAQ·연혁·서비스 등은 게시판으로 만들고 섹션에서 연결 |
| AI | 화면 안 버튼 → 서랍, 기능 스위치(기본 꺼짐), 사용 한도 공유, `ai_usage_log` | 같은 방식으로 추가. 별도 AI 메뉴 · 새 로그 표 만들지 않음 |
| 권한 | `TENANT_ADMIN` · `TENANT_VIEWER` | 보기 전용은 읽기만. 작성자/검토자/발행자 역할은 후속 |
| 새 기능 | 기능 스위치 + 요금제 한도 (CLAUDE.md 8.2). FREE · BASIC 은 섹션 '고정' 요금제(`section_manage.FIXED_PLANS` — 섹션 추가 · 삭제 불가), 추가 게시판도 0개 | `CUSTOM_PAGES` 스위치(기본 꺼짐), 요금제별 페이지 수 한도 (PART C 4번) |

## 1. 핵심 목표와 업무 경계

- **페이지 관리 = 보이는 화면:** 페이지 목록, 주소, 메뉴 표시, 페이지별 SEO, 섹션 구성, 미리보기.
- **콘텐츠 관리 = 화면에 들어갈 반복 정보:** 게시판 기반 구조화 콘텐츠(FAQ·연혁·서비스·후기 등)와 섹션 연결.
- **직접 입력:** 한 페이지에서만 쓰는 배너 문구·이미지는 섹션 설정에 저장 (지금 방식 그대로).
- **참조 연결:** 여러 페이지에서 재사용하는 목록형 정보는 게시판에 등록하고 "게시판 연결" 섹션으로 보여 줌.
- **범위 제외:** 게시판·미디어·사이트·사용자 관리 메뉴 자체의 재설계.

## 2. 개발 순서 (확정 결정 반영)

1. **P1 페이지 목록·생성·설정** — `pages` 표, API, 관리자 화면, 메뉴 연결, 주소 검사, 요금제 한도, 기능 스위치.
2. **P2 공개 화면** — 코드형·테마형 템플릿 모두 `/{slug}/{page_key}` 로 직접 만든 페이지를 그림. 페이지별 SEO 메타, 사이트맵.
3. **P3 섹션 구성** — 직접 만든 페이지에 섹션 추가·삭제·정렬·숨김. 관리자 섹션 편집과 인라인 편집 모두.
4. **P4 변경 안전장치** — 주소 변경 리다이렉트, 휴지통(30일), 템플릿 전환 시 처리, 링크 깨짐 안내.
5. **C1 콘텐츠 연결** — "게시판 연결" 섹션(목록·카드·FAQ 아코디언·연혁)과 필드 매핑.
6. **후속** — 초안/발행 분리와 버전, 승인 절차, 예약 발행, 다국어, AI 일괄 작성, 콘텐츠 성과.

## 3. 메뉴 구조

```text
페이지 관리                       (/admin/pages)
├─ 페이지 목록                    PM-01
├─ 페이지 추가·설정               PM-02
├─ 페이지 편집 (섹션 구성)        PM-03 · PM-04 — 기존 섹션 편집 화면을 페이지 단위로
│   └─ 화면에서 편집 →            홈페이지 인라인 편집 모드로 이동
├─ 콘텐츠 연결 (섹션 설정 안)     PM-05
└─ 미리보기                       PM-06 (발행·버전은 후속)

콘텐츠 관리
├─ 콘텐츠 목록                    CM-01 — 게시판 글 통합 목록(/admin/posts) 재사용
├─ 콘텐츠 작성·수정               CM-02 — 게시글 편집 화면 재사용
├─ 콘텐츠 유형·필드               CM-03 — 게시판 만들기 · 필드 설정 재사용 + "콘텐츠형 게시판" 프리셋
├─ 카테고리·태그                  CM-05 — 게시판 분류 재사용
└─ (후속) 공통 블록 · 승인 · 다국어 · AI 센터 · 성과
```

> 기존 "콘텐츠(`/admin/content`)" 메뉴는 페이지 관리로 흡수한다. 홈 페이지 편집 = 지금의 섹션 편집 화면.
> (T-238 구현) 페이지 편집은 `/admin/pages/{주소}` 의 [섹션] · [설정] 탭, 섹션 편집은 `/admin/pages/{주소}/sections/{id}`. 예전 `/admin/content` 주소는 새 주소로 보낸다. 새 빈 페이지는 숨김으로 만들어 채운 뒤 공개한다.

## PM-02. 페이지 추가·설정

**입력:** 페이지명*(30자), 주소*(영문 소문자·숫자·하이픈 2~40자), 상위 페이지(메뉴 묶음), 시작 방식(빈 페이지 / 기존 페이지 복제 / 템플릿 추천 구성), 메뉴 표시, 공개 상태(공개 / 숨김 — 숨김은 주소로도 404), SEO 탭(제목, 설명, OG 이미지, 검색 제외).

(T-247) 추천 구성은 `GET /pages/recipes` — 코드형은 템플릿 샘플의 서브 페이지 구성(게시판 페이지 제외) 그대로 · 샘플 값, 테마형은 소개 페이지 · 서비스 안내 · 오시는 길(메인 배너 없이, 갤러리는 스위치 켜졌을 때만). 만들 때 `recipe` 로 섹션을 함께 넣고 페이지 섹션 한도까지만.

(T-245) OG 이미지는 페이지 설정 > 검색 노출의 '공유 이미지' — 비우면 사이트 SEO 공유 이미지를 쓴다. 안 쓰는 사진 정리(30일)는 페이지 공유 이미지를 지우지 않는다(휴지통 페이지 포함). 홈은 사이트 SEO 설정을 쓰므로 홈 페이지 설정에는 SEO 칸 대신 그 화면 바로 가기만 둔다.

**검증 (서버):** 필수값, 주소 형식, 같은 사업체 안 중복(휴지통 포함), 예약 주소, 현재 템플릿 기본 페이지 키와 충돌, 요금제 한도.
**주소 변경:** 이전 주소 → 새 주소 301 리다이렉트 자동 등록, 메뉴는 자동 갱신, 섹션 버튼 링크에 남은 이전 주소는 목록으로 안내.
**AI (스위치 켜진 경우):** 페이지명·업종으로 SEO 제목·설명 초안 — 기존 `/ai/assist/seo` 를 페이지 단위로 확장.

(T-248) `POST /ai/assist/page_seo` (`page_id`, 말투) — 사업체 정보 + 그 페이지 이름 · 그 페이지의 보이는 섹션 제목 · 지금 페이지 검색 문구로 검색 제목(60자) · 설명(160자). 스위치 · 한도는 사이트 SEO AI 와 같다(`AI_SITE_ASSIST`, 문구 추천 한도). 페이지 설정 > 검색 노출의 [✨ 페이지 내용으로 채우기] → 고른 칸만 폼에 채우고 저장은 관리자가. 홈은 사이트 SEO 를 쓰므로 버튼이 없고 서버도 400.

## PM-03. 페이지 편집

새 3단 편집기를 만들지 않는다. 두 가지 기존 편집 방식을 페이지 단위로 확장한다.

| 방식 | 화면 | 이번에 바뀌는 것 |
|---|---|---|
| 관리자 섹션 편집 | `/admin/pages/{page_key}` — 지금 `/admin/content` 와 같은 화면 | 페이지 선택, 섹션 추가(PM-04), 페이지 이동 |
| 화면에서 편집 | 홈페이지 `/{slug}/{page_key}` 인라인 편집 모드 | 직접 만든 페이지에서도 편집 모드, 섹션 추가 버튼 |

- PC·태블릿·모바일 미리보기는 관리자 미리보기(`/preview`)에 페이지 선택과 기기 폭 전환을 추가한다. (T-246) PC 미리보기 아래 [PC · 태블릿 · 휴대폰] 버튼, 태블릿 768px · 휴대폰 390px 은 `?device=` 로 그 폭의 틀(iframe) 안에 같은 미리보기를 띄운다 — 틀 안이 실제 그 폭이라 미디어 쿼리가 그대로 적용된다.
- 기기별 스타일 따로 지정 · 위젯 자유 배치는 **하지 않는다** (코드형 템플릿은 레이아웃이 고정).
- 자동저장·저장 상태 표시·이탈 경고는 지금 섹션 편집 동작을 그대로 쓴다.

## PM-04. 섹션 추가 (섹션 라이브러리)

- 고를 수 있는 섹션은 **현재 템플릿이 그릴 수 있는 종류만**. (T-241 구현) 코드형은 매니페스트에 목록을 따로 두지 않고 백엔드가 템플릿 샘플 콘텐츠의 서브 페이지 섹션(메인 전용 · 게시판 제외)을 뽑는다 — 사진+글은 배치(layout)마다 하나, 샘플 값을 그대로 넣는다.
- 테마형 템플릿은 기존 테마 섹션(HERO_BANNER · INTRO · SERVICES · GALLERY · FAQ …)을, 코드형은 SUB_HERO · CONTENT_BLOCK · HISTORY_TIMELINE 등을 고른다.
- (T-262) 코드형은 **기본 페이지 · 직접 만든 페이지 모두**에 연결 섹션 '게시판 연결'(`BOARD_LATEST`) · '콘텐츠 연결'(`CONTENT_LIST`, `CONTENT_MANAGE` 켜졌을 때)을 더할 수 있다. 기본 페이지의 정해진 구성은 더하기 · 지우기 불가 — 한도 응답 `deletable_types` 가 지울 수 있는 종류(연결 섹션만)를 알려 준다.
- 추가한 섹션은 샘플 문구(`is_sample=true`)로 채워 바로 모양이 보이게 한다.
- 저장은 기존 `sections` · `section_settings` 그대로 (`page_key` 만 새 페이지 키).

| 종류 (예) | 기본 제공 | 비고 |
|---|---|---|
| 페이지 상단(SUB_HERO) | 제목, 설명, 배경 이미지 | 새 페이지 기본 첫 섹션 |
| 사진+글(CONTENT_BLOCK) | 이미지, 제목, 본문 | 좌우 배치 변형 |
| 카드 목록 | 반복 카드 | 직접 입력 |
| CTA | 문구, 버튼 | 링크는 페이지 선택 또는 주소 |
| FAQ | 질문·답변 | 직접 입력 또는 게시판 연결(PM-05) |
| 게시판 연결 | 게시판 선택 | C1 단계 |

## PM-05. 콘텐츠 연결 (C1 단계)

"게시판 연결" 섹션의 설정 안에서 데이터 소스를 고른다.

```text
┌─────────────────────────────────────────┐
│ 섹션: 서비스 카드                        │
│ 입력 방식 ( ) 직접 입력 (●) 게시판 연결  │
│ 게시판 [서비스 소개 ▼]                  │
│ 분류 [전체 ▼] 정렬 [최신순 ▼] 개수 [6]   │
│ 보여 주는 방식 [카드 ▼]                 │
│ 필드 매핑                               │
│  카드 제목 ← 제목                       │
│  설명     ← 요약(사용자 필드)            │
│  이미지   ← 대표 이미지                  │
│  링크     ← 글 상세                      │
│ [미리보기]                      [적용]  │
└─────────────────────────────────────────┘
```

**구현 (T-243, 2026-11-25 결정):** 테마형 템플릿만 — 예전 '최신 글'(`BOARD_LATEST`)을 '게시판 연결'로 넓혔다. 칸 매핑은 고정(제목 · 본문 요약 · 본문 첫 사진 · 공개일 + 글 목록에 표시로 고른 칸, 연혁은 `year` 칸 → 없으면 공개일의 해). 개수 3~12, 정렬 최신순 · 오래된 순 · 게시판 순서. 글은 `GET /public/site/{slug}/boards/{board}/section-posts`(비밀글 제외, 회원 전용 · 지운 게시판 404). 사용 위치는 `GET /boards/{id}/usage` — 게시판 설정 화면과 휴지통 확인에. 코드형 연결 · 사용자 칸 매핑은 후속.

**예외:** 비공개·삭제 게시판 → 섹션은 빈 상태로 그리고 관리자에게만 "연결된 게시판이 없어요" 표시. 비밀글·회원 전용 글은 공개 섹션에 절대 노출 안 함. 빈 결과 문구 설정. 게시판 삭제 시 연결된 페이지 목록 안내.

## PM-06. 미리보기 (발행·버전은 후속)

- MVP: 저장 즉시 공개 (지금 방식). 숨김 상태 페이지는 관리자 미리보기에서만 보임 → "숨김 페이지에서 내용을 준비하고 공개로 바꾸기"가 간이 초안 역할.
- (T-244 구현) 페이지 목록 · 편집 화면의 [미리보기] → `POST /pages/{id}/preview` 10분 토큰 → 홈페이지 `/{slug}/preview?draft=…&page={주소}`. 미리보기 응답에만 그 숨김 페이지가 들어가고, 섹션 [미리보기]도 같은 방식. 공개 페이지는 [화면에서 편집]으로 홈페이지를 새 탭에 연다.
- 후속(별도 설계 문서): 페이지 초안/공개 버전 분리, 버전 비교·롤백, 예약 발행, 발행 이력. 인라인 편집·공개 API·사이트 캐시·템플릿 되돌리기(7일) 모두 영향을 받으므로 따로 설계한다.

## CM-01. 콘텐츠 목록 — 재사용

게시판 글 통합 목록(`/admin/posts`)에 "콘텐츠형 게시판만 보기" 필터를 추가한다. 사용 위치(어느 페이지의 어느 섹션이 이 게시판을 보여 주는지) 칸 추가.

**구현 (T-249):** `boards.is_content`(마이그레이션 0063, 기본 꺼짐) — 콘텐츠형 프리셋으로 만들면 켜지고, 게시판 설정 > 기본 정보의 '콘텐츠형 게시판'으로 바꾼다(복제본도 그대로). 게시글 관리의 '게시판 종류: 콘텐츠형 게시판만'(`GET /posts?content=true`) — 게시판 고르기도 콘텐츠형만, 콘텐츠형이 아닌 게시판을 골라 둔 채 켜면 게시판 · 카테고리 조건을 푼다. 사용 위치는 게시판 설정의 '사용 위치'(T-243)로 보고, 글 목록에는 칸을 두지 않는다.

## CM-03. 콘텐츠 유형·필드 — 재사용 + 프리셋

게시판 만들기에 "콘텐츠형" 프리셋을 추가한다: 서비스 소개 · FAQ · 연혁 · 의료진/팀 소개 · 후기. 프리셋은 필드 구성과 방문자 글쓰기 꺼짐, 목록 화면 숨김(섹션으로만 노출)을 미리 채운다.

# PART C. 데이터·API·검증 설계

## 1. 새 표

```sql
-- 페이지 (템플릿 기본 페이지 + 직접 만든 페이지)
CREATE TABLE pages (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id     UUID NOT NULL REFERENCES tenants(id),
  page_key      VARCHAR(50) NOT NULL,          -- 주소, sections.page_key 와 같음
  title         VARCHAR(30) NOT NULL,
  origin        VARCHAR(10) NOT NULL,          -- TEMPLATE | CUSTOM
  parent_key    VARCHAR(50),                   -- 메뉴 묶음 (1단계)
  show_in_menu  BOOLEAN NOT NULL DEFAULT true,
  is_public     BOOLEAN NOT NULL DEFAULT true,
  display_order INT NOT NULL DEFAULT 0,
  seo_title       VARCHAR(60),
  seo_description VARCHAR(160),
  og_image_url    VARCHAR(500),
  noindex         BOOLEAN NOT NULL DEFAULT false,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ
);
CREATE UNIQUE INDEX uq_pages_tenant_key ON pages(tenant_id, page_key);  -- 휴지통 포함 중복 금지

-- 주소 변경 리다이렉트
CREATE TABLE page_redirects (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID NOT NULL REFERENCES tenants(id),
  from_key VARCHAR(50) NOT NULL,
  to_key   VARCHAR(50) NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
-- 두 표 모두 RLS 표준 정책 적용, 해지 사업체 파기 목록(PURGE)에 추가
```

- 템플릿 기본 페이지(`origin=TEMPLATE`)는 페이지 목록을 읽을 때 지금 템플릿 기준으로 맞춘다 — 없는 것은 만들고, 다른 템플릿의 것은 숨겼다가 그 템플릿으로 돌아가면 SEO 값 그대로 되살린다. 마이그레이션은 기존 사업체의 홈 행만 만든다 (T-237).
- 주소를 바꾸면 섹션 · 하위 페이지 · 저장한 메뉴가 따라가고 `page_redirects` 에 남는다. 이전 기록은 새 주소로 곧장 이어 붙이고, 새 주소를 쓰던 기록은 지운다.
- 페이지를 지우면 그 페이지 섹션도 같은 시각으로 숨기고, 복구할 때 그 시각의 섹션만 살린다. 복제는 섹션 · 섹션 값을 복사한 숨김 페이지(갤러리 사진 제외).
- 섹션·섹션 설정 표는 바꾸지 않는다. 직접 만든 페이지 삭제 시 그 `page_key` 섹션도 소프트 삭제.
- 요금제별 직접 만든 페이지 수 한도는 기존 요금제 한도 설정에 추가 (값은 결정 필요).

## 2. API (`/api/v1`, 공통 응답 규격)

| 메서드 | 주소 | 설명 |
|---|---|---|
| GET | `/pages` | 목록 (기본 + 직접, 휴지통, 한도, 스위치) — 스위치가 꺼져도 볼 수 있음. 아래는 모두 `CUSTOM_PAGES` 필요 |
| POST | `/pages` | 추가 (`CUSTOM_PAGES` 스위치 · 한도 · 주소 검사) |
| GET | `/pages/check-key?key=` | 주소 사용 가능 여부 (입력 중 확인) |
| PATCH | `/pages/{id}` | 이름·주소·상위·메뉴·공개·SEO 수정 (주소 변경 시 리다이렉트 등록) |
| POST | `/pages/{id}/duplicate` | 복제 (섹션 포함) |
| PATCH | `/pages/reorder` | 순서 |
| DELETE | `/pages/{id}` | 휴지통 이동 (기본 페이지·홈은 403) |
| POST | `/pages/{id}/restore` | 휴지통 복구 |
| GET | `/sections?page_key=` | 기존 API 에 페이지 필터 (T-238) |
| GET | `/public/site/{slug}` | 응답에 `pages` — 템플릿 기본 페이지(숨김 · SEO) + 직접 만든 공개 페이지(스위치 켜진 사업체만) (T-239) |

## 3. 수용 기준

1. 스위치가 켜진 사업체는 페이지를 추가하고, `/{slug}/{주소}` 에서 바로 볼 수 있다 (코드형·테마형 모두).
2. 중복·예약·형식 오류 주소는 서버가 막고 이유를 보여 준다.
3. 새 페이지가 메뉴 설정 선택지에 나타나고, 메뉴에 넣으면 헤더에 보인다.
4. 직접 만든 페이지에 템플릿이 그릴 수 있는 섹션을 추가·정렬·숨김할 수 있다 (관리자 · 인라인 편집 모두).
5. 페이지별 SEO 가 `<title>` · 메타 · OG · 사이트맵에 반영되고, 숨김·검색 제외 페이지는 사이트맵에서 빠진다.
6. 주소를 바꾸면 이전 주소가 새 주소로 301 이동한다.
7. 삭제한 페이지는 30일 동안 복구할 수 있고, 메뉴와 공개 화면에서 즉시 빠진다.
8. 템플릿을 바꿔도 직접 만든 페이지 내용은 사라지지 않는다.
9. 다른 사업체 페이지는 조회·수정할 수 없다 (RLS 테스트).
10. 요금제 한도를 넘으면 422 `PLAN_LIMIT_EXCEEDED`, 화면은 업그레이드 안내.
11. 기존 홈·템플릿 페이지·게시판·공지 주소가 회귀하지 않는다.
12. AI 결과는 사용자가 확인하기 전에는 저장·공개되지 않는다.

| 5 | 초안/발행 분리를 오픈 전에 할지 | **오픈 뒤.** 숨김 페이지로 준비 → 공개 전환으로 대체 |
