## 1. 개요

### 1.1 목표

템플릿이 정해 준 페이지만 쓰던 고객이 **자기 손으로 페이지를 늘리게** 한다.
예를 들어 회사는 '서비스 안내' 페이지를 새로 만들고, 병원은 의료진 소개를 게시판으로 관리하면서 그 글을 페이지에 띄운다.

### 1.2 기간과 범위

- **기간**: 2026-11-24 ~ 2026-11-26
- **태스크**: T-237 ~ T-249 (13개 태스크, PR #200 ~ #212)
- **기준 문서**: `docs/CMS_Page_Content_Plan_v1.0.md` (PM-01 ~ PM-07, CM-01 ~ CM-05, PART C), `TASK.md` Phase 22
- **주요 결정 (2026-11-24)**: 요금제 한도 FREE 0 · BASIC 0 · STANDARD 10 · PREMIUM 무제한, 기존 "콘텐츠" 메뉴를 페이지 관리로 합침, 주소는 `/{slug}/{주소}` 한 단계, 초안/발행 분리는 오픈 뒤

### 2.2 고객이 할 수 있게 된 일

- 페이지를 **빈 페이지 · 기존 페이지 복제 · 추천 구성** 중 하나로 만든다. 새 페이지는 숨김으로 시작해 채운 뒤 공개한다.
- 페이지마다 섹션을 넣고 · 순서를 바꾸고 · 숨긴다 (관리자 화면과 홈페이지 편집 모드 모두).
- 페이지마다 검색 제목 · 설명 · 공유 이미지 · 검색 제외를 정하고, AI 초안을 받아 고른 칸만 채운다.
- 숨김 페이지를 미리보기로 보고, PC · 태블릿 · 휴대폰 폭으로 바꿔 본다.
- 주소를 바꿔도 예전 링크는 301 로 새 주소에 이어진다. 지운 페이지는 30일 안에 되살린다.
- 서비스 소개 · FAQ · 연혁 · 의료진 · 후기를 게시판 글로 관리하고, "게시판 연결" 섹션으로 페이지에 띄운다.
- 게시글 관리에서 콘텐츠형 게시판 글만 모아 본다.

### 2.3 막아 둔 것 (안전 장치)

- 주소는 형식(영문 소문자 · 숫자 · 하이픈 2~40자) · 예약어 · 사용 중 · 휴지통 주소를 서버가 막는다 (400 · 409, `field: page_key`).
- 홈 · 템플릿 기본 페이지는 지울 수 없고 (403), 기본 페이지 주소 · 상위는 바꿀 수 없다 (400).
- `CUSTOM_PAGES` 스위치가 꺼지면 목록만 보이고 쓰기는 403, 한도를 넘으면 422 `PLAN_LIMIT_EXCEEDED`.
- 템플릿을 바꿀 때 새 템플릿 기본 페이지와 주소가 겹치는 직접 페이지가 있으면 409 로 막고 이름을 알려 준다.
- 게시판 연결 섹션은 비밀글을 빼고, 회원만 읽는 · 지운 · 비활성 게시판은 404.
- 병원 업종은 후기(리뷰형) 프리셋이 막혀 있다 (결정 D-14 그대로).

## 7. 배운 점

- **섹션 표를 바꾸지 않고 `page_key` 로 잇는 설계가 효과가 컸다.** 기존 홈 · 템플릿 화면 회귀 없이 13개 PR 을 냈다.
- **점검(Check)을 중간에 한 번 한 것이 큰 구멍을 잡았다.** 테스트는 다 통과했지만 '숨김으로 준비 → 공개' 흐름이 실제로는 막혀 있었다 (T-244).
- **두 템플릿 방식(코드형 · 테마형) 계정으로 모두 확인**하니 테마형에서만 나는 문제를 머지 전에 볼 수 있었다.
- **DB 변경이 필요한 항목(3-5)은 따로 떼어 승인을 받은 뒤** 진행했다. 다른 항목이 DB 결정을 기다리지 않았다.
- **감사 로그 같은 '부수 기록'은 새 칸을 더할 때 빠지기 쉽다.** 칸을 더하면 응답 · 복제 · 감사 로그를 함께 찾아본다.
