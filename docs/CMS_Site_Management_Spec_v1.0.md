# 사이트 관리 기획서 v1.0

> 원본 와이어프레임: `docs/mockups/기획/사이트관리/CMS_Site_Management_Plan_Wireframes.html` (2026-11-06)
> 이 문서는 실제 구현과 맞춘 규칙이다. 와이어프레임과 다르게 정한 부분은 **결정** 으로 표시한다.

## 1. 메뉴 구조 (T-221 ✅)

관리자 왼쪽 메뉴의 **대시보드 바로 아래** 2뎁스 그룹.

| ID | 메뉴 | 주소 | 상태 |
|---|---|---|---|
| SM-01 | 사이트 기본정보 | `/admin/site/info` | 기존 화면 이동 (T-221) · 칸 확장 (T-222) |
| SM-02 | 메뉴 관리 | `/admin/site/menu` | 기존 화면 이동 (T-221) · 트리 (T-223) |
| SM-03 | 약관 · 정책 관리 | `/admin/site/policies` | 기존 화면 이동 (T-221) · 버전 (T-224) |
| SM-04 | SEO 설정 | `/admin/site/seo` | 기존 화면 이동 (T-221) · 보완 (T-225 ✅) |
| SM-05 | AEO 설정 | `/admin/site/aeo` | 신규 (T-221) |
| SM-06 | GEO 설정 | `/admin/site/geo` | 신규 (T-221) |

- `/admin/site` → 기본정보. 예전 주소 `/admin/seo` · `/admin/policies` · `/admin/content?tab=settings` 는 새 주소로 넘긴다 (홈페이지 편집 모드의 [사이트 기본정보 열기] 링크도 새 주소).
- 콘텐츠 편집의 '공통 설정' 탭은 없앴다 — 콘텐츠 편집은 섹션만.
- SEO · AEO · GEO 는 `SEO_WIZARD` 기능 플래그를 따른다 (꺼지면 그 3개 메뉴만 숨김, 저장 API 403). 2뎁스 메뉴에도 BETA · NEW 표시.
- 모바일 하단 [더보기]에는 '사이트 관리' 하나 (기본정보로 이동).
- **결정:** 와이어프레임의 '페이지 관리' · '미디어 관리' · '회원 관리 → 가입 설정' · 상단 사이트 선택은 넣지 않는다 (사업체 하나 = 사이트 하나).

## 2. 공통 화면 규칙

- 헤더 경로 `홈 / 사이트 관리 / 화면`.
- 사이트 관리 모든 화면은 아래 고정 저장 막대: "저장되지 않은 변경사항이 있습니다." · [변경 취소] · [변경사항 저장]. 바꾼 것이 없으면 버튼이 꺼진다. 보기 전용 계정은 막대가 없고 입력이 잠긴다.
- 저장하지 않고 다른 화면으로 가거나 창을 닫으면 확인을 받는다.
- 저장 실패는 알림으로, 입력은 그대로 남긴다.
- 고칠 수 없는 값(예: 글자 수 초과)이 있으면 저장 막대가 까닭을 보여 주고 저장을 막는다 (T-225).

## 3. 사이트 기본정보 (SM-01, T-222 ✅)

- **카드 4개:** 브랜드 정보(사이트명 · 회사명 · 로고 · 파비콘) / 사업자 · 연락처(대표자 · 사업자등록번호 · 통신판매업 신고번호 · 업태 · 종목 · 대표 전화 · 고객센터[대표번호와 동일] · 팩스 · 대표 이메일 · 우편번호 · 기본 · 상세 주소 · 주차) / 운영시간 / 개인정보 담당 · 표시 설정(보호책임자 · 문의 이메일 · 저작권 문구 · 공개 항목 · 푸터 미리보기). 아래 저장 막대 · 나가기 확인.
- **결정 — 필수값:** 와이어프레임의 * (사이트명 · 회사명)은 강제하지 않는다. 비우면 사업체 이름을 쓴다 (기존 사업체가 저장하지 못하는 일이 없게).
- **검증:** 글자 수(사이트명 · 회사명 100, 통신판매업 50, 업태 50, 종목 100, 임시 안내 200, 보호책임자 50, 저작권 200), 전화 · 고객센터 · 팩스는 국내 번호 또는 `+` 국제번호, 이메일 형식, 우편번호 숫자 5자리, 사업자등록번호 10자리(하이픈 자동). 통신판매업 신고번호는 자유 글자.
- **요일별 운영시간** `weekly_hours` `{mon..sun: {status: open|closed|24h, open, close, break_start, break_end}}`: 영업이면 여는 · 닫는 시각 필수, 같으면 안 됨, 닫는 시각이 이르면 다음 날 새벽 종료(닫는 시각 `24:00` 허용), 점심시간은 둘 다 넣고 영업시간 안. 휴무 · 24시간은 시각을 비운다. 오류 field 는 `weekly_hours.{요일}`. 처음 켜면 월~금 09:00~18:00 · 주말 휴무, [모든 요일에] 복사.
- **결정 — 예전 운영시간 글:** 자유 글자(평일 · 토요일)는 형식이 제각각이라 바꾸지 않는다. 표가 비어 있으면 예전 글을 그대로 보여 주고(표를 끄면 다시 입력 가능), 표가 있으면 표를 쓴다. 휴무일 안내(`hours_note`) · 임시 운영 안내는 둘 다에 붙는다.
- **공개 항목** `hidden_fields` (숨긴 묶음 키, 비면 모두 공개 — 기존 화면 그대로): 회사명 · 대표자 · 주소(우편번호 · 상세 포함) · 전화번호(대표 · 고객센터) · 팩스 · 이메일 · 사업자 정보(등록번호 · 통신판매업 · 업태 · 종목) · 개인정보 보호책임자(이메일 포함). 숨긴 값은 서버가 공개 응답에서 `null` 로 빼고(`site_settings.public_view`), 공개 응답 `hidden_fields` 로 어떤 묶음을 숨겼는지만 알린다 — 홈페이지는 숨긴 주소 · 전화를 오시는 길 섹션 값 · 지도 · 좌표로 대신 채우지 않는다. 약관 기본 문안 · 사이트 닫힘 화면 전화도 공개 값만.
- **홈페이지 반영:** 사이트명 → 공개 응답 `tenant.name`(헤더 · 탭 제목 · 메타 기본값). 푸터(테마형 · 코드형): 회사명(없으면 사이트명) · 대표자 · 사업자등록번호 · 통신판매업 · 업태 · 종목 · (우편번호) 주소 · TEL · 고객센터 · FAX · 이메일 · 요일별 시간(같은 시간 요일 묶음 "월~금") · 휴무 · 임시 안내 · 보호책임자 · 저작권 문구(없으면 기본 문구). JSON-LD: `legalName` · `faxNumber` · `postalCode` · `openingHoursSpecification`(점심시간은 둘로, 24시간은 00:00~23:59, 휴무 제외 — 예전 자유 글은 넣지 않음).
- 개인정보처리방침 기본 문안의 책임자 = 보호책임자(없으면 대표자), 연락 이메일 = 개인정보 문의 이메일(없으면 대표 이메일). 이용약관 사업자 이름 = 회사명. 약관 기본 문안에서 숨긴 항목은 "비공개", 비워 둔 항목은 예전처럼 "(사이트 설정에서 입력해 주세요)".
- 저장: `site_settings` 칸 + `weekly_hours` · `hidden_fields` JSONB (마이그레이션 0059). 저장하면 사이트 캐시를 비운다.
- **범위 밖:** 주소 검색 버튼(외부 API — 직접 입력), 템플릿별 필수 공개 항목 강제, 사업자 실제 확인.

## 4. 메뉴 관리 (SM-02, T-223 ✅)

- **화면:** 왼쪽 '사이트 메뉴 구성' 트리(단계별 들여쓰기 · 유형 · 새 창 · 숨김 · 경고 표시, 같은 단계 안 위 · 아래 버튼, [메뉴 추가]) + 오른쪽 '메뉴 설정'(메뉴명 · 상위 메뉴 · 연결 유형 · 연결 대상 · 열기 방식 · 보이기 · [선택 메뉴 삭제]). 아래 저장 막대 · 나가기 확인. 저장한 메뉴는 [템플릿 기본 메뉴로 되돌리기].
- **결정 — 끌어서 옮기기:** 위 · 아래 버튼과 상위 메뉴 고르기로 대신한다 (키보드 · 휴대폰에서도 같은 방법).
- **규칙:** 최대 3단계 · 60개, 메뉴명 1~20자. 상위 메뉴로 자기 자신 · 하위 메뉴, 넣으면 3단계를 넘는 메뉴는 고를 수 없다(순환 금지). 연결 유형: 페이지(코드형은 템플릿 페이지와 하위 페이지, 테마형은 홈 섹션 — 누르면 그 섹션으로 내려감) / 게시판 / 외부 URL(http · https 만, 500자) / 하위 메뉴 묶음(연결 대상 없음). 새 창은 `target="_blank" rel="noopener noreferrer"`.
- **경고 · 제외:** 사용 안 함 · 지운 게시판, 템플릿에 없는 페이지, 하위 메뉴 없는 묶음은 관리자에서 경고하고 홈페이지 메뉴에서는 빠진다(빈 묶음도). 회원 전용 게시판은 안내만 하고 메뉴에 남긴다(방문자는 로그인 안내).
- **삭제:** 메뉴만 지운다 — 페이지 · 게시판은 그대로. 하위 메뉴가 있으면 '하위 메뉴는 위로 옮기기' / '함께 삭제'를 고른다. 숨기면 하위 메뉴도 함께 숨긴다.
- **결정 — 저장 방식 (DB 변경 없음):** `site_settings.menu_items` 안에 템플릿마다 트리 `{scope: "code:{code}" | "theme", nodes, known}`. 템플릿을 바꿔도 다른 템플릿용 트리는 남는다. 트리가 없으면 예전 방식(이름 · 숨김 · 순서 덮어쓰기)을 그대로 쓴다.
- **결정 — 이어받기:** 처음 열면 지금 홈페이지 메뉴(예전 저장값 포함)를 트리로 바꿔 보여 준다. 코드형 하위 페이지(`{code}.menu.json` 의 `parent`)와 페이지 하위 탭에 넣은 게시판(T-216)은 그 페이지의 하위 메뉴로 넣는다. 저장하기 전까지 홈페이지는 바뀌지 않는다.
- **새 섹션 · 게시판:** 트리를 저장할 때 있던 후보(`known`)가 아닌 것만 홈페이지 메뉴 끝에 자동으로 붙는다. 저장 때 일부러 뺀 메뉴는 다시 붙지 않는다. 게시판 복사본 · '메뉴에 넣지 않음'으로 만든 게시판은 숨김으로 들어간다.
- **홈페이지:** 테마형 Navbar · hospital-a Header — 넓은 화면은 마우스를 올리거나 키보드로 들어가면 하위 메뉴 드롭다운, 3단계는 드롭다운 안 들여쓰기. 휴대폰 · 접힌 메뉴는 들여쓰기 목록. 사이트맵은 트리에서 숨긴 페이지 · 게시판을 뺀다.
- **API:** `GET /api/v1/site-settings/menu` → `{mode, reorderable, saved, max_depth, nodes, pages: [{key, label, parent}], boards: [{id, name, slug, active, member_only, menu_parent}], items}` (`items` = 맨 위 후보가 트리에서 보이는지 — 게시판 화면 '상단 메뉴에 표시'), `PUT` `{nodes}` (검증 실패 400 `VALIDATION_ERROR`), `DELETE` = 기본 메뉴로. 공개 응답 `site_settings.menu_tree` (정리된 트리 `{label, type, target, slug, new_window, children}`, 트리를 저장하지 않았으면 `null`) · `menu_hidden` · `menu_items`(예전 방식 값만).

## 5. 약관 · 정책 관리 (SM-03, T-224 ✅)

- **화면:** '정책 목록'(문서명 · 버전 · 상태 · 시행일(다음 예약) · 연결) + '선택 문서 편집'([내용 편집] · [버전 이력]). 법률 확인 안내는 늘 보인다.
- **결정 — 문서 종류:** 이용약관 · 개인정보처리방침 2개만. 와이어프레임의 '개인정보 수집·이용 동의' · '마케팅 정보 수신 동의' 문서와 [정책 등록] · 가입 설정 연결은 다음에 회원 가입 설정과 함께.
- **상태:** 초안 → 예약(시행일) 또는 바로 공개 → 다음 공개 때 보관. 예약 취소 → 초안. 문서마다 공개본 하나 · 작업 중(초안 · 예약) 하나 (DB 부분 유니크 인덱스).
- **공개본 수정:** 직접 고치지 않는다 — [새 버전 만들기]가 공개본(없으면 기본 문안)을 복사한 초안을 만든다. 초안만 고칠 수 있고 저장해도 홈페이지는 그대로. [기본 문안으로 채우기] 제공.
- **공개 · 예약:** 변경 내용 요약이 있어야 한다(500자). 바꾼 내용을 저장한 뒤에만. 시행일(한국 시간)을 비우거나 지난 시각이면 바로 공개, 앞날이면 예약(1년 안). 확인 창을 거친다.
- **예약 시행:** Celery `release_due_policies` 5분마다 — 시행일이 지난 예약을 `FOR UPDATE SKIP LOCKED` 로 잡아 같은 트랜잭션에서 공개본 보관 · 예약 공개. 여러 번 · 겹쳐 돌아도 같은 결과, 실패하면 Celery 재시도 + 다음 5분에 다시. 공개되면 사이트 캐시를 비운다.
- **기본 문안:** 버전이 하나도 없으면 사이트 기본정보 · 요금제로 그때그때 만든다(T-200 그대로). 마이그레이션 0060 은 이미 고친 글을 v1 공개본으로 옮긴다(시행일 = 마지막 수정 시각).
- **홈페이지:** 제목 아래 'v3 · 시행일 2026.12.01', 아래 '이전 버전' 목록(보관본, 최신부터) · `?v=2` 로 보관본 보기("이전 버전이에요" 안내 + 지금 버전 링크). 초안 · 예약 · 없는 버전은 404.
- **동의 기록** `consent_records {kind, policy_version_id, version, subject_type: member | board_post | inquiry, subject_id, agreed, source, created_at}`: 회원가입(약관 · 개인정보, `member_join` · `member_join_social`) · 방문자 글쓰기(개인정보, `board_write`) · 상담 글 · 예약 · 간편상담(화면의 필수 체크박스 — `terms_agree` · `privacy_agree` 를 보낸 경우만, `inquiry` · `consult_board`)을 저장할 때 같은 트랜잭션에서 그때의 공개 버전으로 남긴다. 기본 문안이면 버전 없음. 새 버전이 나와도 덮어쓰지 않는다.
- **결정 — 재동의 · 조회:** 새 버전 공개로 일괄 재동의를 받지 않는다(와이어프레임 '별도 설계'). 동의 기록 조회 화면은 회원 관리와 함께 다음에. 체크박스가 없는 기본 문의 폼(테마형)은 기록하지 않는다 — 체크박스를 둘지는 법률 확인 때 정한다.
- **API:** `GET /api/v1/site-settings/policies` → 문서마다 `{…공개 문서, default_body, working, versions}`, `POST /policies/{kind}/draft` (작업 중이 있으면 409), `PUT /policies/{kind}/draft {body, summary}` (예약 중이면 409), `POST /policies/{kind}/publish {effective_at?}`, `POST /policies/{kind}/cancel-schedule`, `GET /policies/{kind}/versions/{n}`. 공개 `GET /api/public/site/{slug}/policies/{kind}` 에 `version · effective_at · history`, `GET …/policies/{kind}/versions/{n}` (공개 · 보관본만).
- 저장: `policy_versions` · `consent_records` (RLS, 해지 사업체 파기 목록) — 마이그레이션 0060. `site_settings.terms_body` · `privacy_body` 는 더 쓰지 않는다(옮긴 뒤 남겨 둠).

## 6. AEO 설정 (SM-05, T-221 ✅)

- **결정 — 원본은 FAQ 게시판:** 와이어프레임의 질문 · 답변 입력칸 대신, FAQ 유형 게시판의 글을 질문(제목) · 답변(본문 글자)으로 쓴다. 화면에 실제로 보이는 내용과 구조화 데이터가 어긋나지 않게 하고, 같은 질문을 두 곳에서 관리하지 않기 위해서다 (와이어프레임 06 "공개된 FAQ 가 Q&A 원본").
- 화면: FAQ 게시판마다 질문 목록(순서 · 질문 · 답변 앞부분 · 구조화 데이터 넣음/빠짐 · [수정]), [질문 추가]는 그 게시판 글쓰기로.
- 빠지는 글과 까닭: 공개 전 글 · 예약 글 · 비밀글 · 답변 없음.
- 게시판마다 [FAQ 구조화 데이터 만들기] — 켜면 검사 결과(넣는 수 · 빠지는 수)와 생성 결과(FAQPage JSON) 미리보기. 사용 안 함 · 회원만 읽는 게시판은 켤 수 없다 (검색엔진이 볼 수 없음).
- FAQ 게시판이 없으면 [FAQ 게시판 만들기] (`/admin/boards/new?example=faq`).
- 홈페이지: 켠 게시판의 목록 화면에 그 화면에 펼쳐 보이는 질문만 `FAQPage` JSON-LD 로 넣는다 (테마형 · 코드형 모두). 비밀글 · 빈 답변 제외, `<` 등 이스케이프.
- API: `GET /api/v1/seo-settings/aeo` → `{faq_board_ids, boards: [{id, name, slug, active, member_only, items: [{post_id, question, answer, public, note}]}]}` · `PUT` `{faq_board_ids}` (FAQ 게시판이 아니거나 없으면 400 `VALIDATION_ERROR` field `faq_board_ids`). 공개 사이트 응답의 게시판에 `faq_jsonld: bool`.
- 저장: `seo_settings.aeo` JSONB `{faq_board_ids: [...]}` (마이그레이션 0058). 지운 게시판은 목록에서 빠진다.

## 7. GEO 설정 (SM-06, T-221 ✅)

- **기업 · 브랜드 정보:** 공식 이름 · 주소 · 연락처는 사이트 기본정보, 공식 사이트 주소는 SEO 대표 주소를 그대로 쓴다 (안내만). 입력: 기업 소개(500자) · 서비스 · 주제 키워드(쉼표, 10개 · 각 30자) · 공식 프로필 주소(10개, http/https).
- **출처 · 근거 정보:** 주장(100자) · 출처 주소 · 최종 확인일, 20개. 관리용이라 홈페이지에 나가지 않는다. 확인일이 1년 지나면 다시 확인 안내.
- **AI 크롤러 접근 정책:** 등록된 User-agent 목록(GPTBot · OAI-SearchBot · ClaudeBot · Claude-SearchBot · PerplexityBot · Google-Extended · Applebot-Extended · CCBot — 서버 상수 `AI_CRAWLERS`, 운영 시점에 각 회사 안내대로 갱신)마다 기존 정책 유지 / 허용 / 차단. 기존 유지는 저장하지 않는다. 목록에 없는 이름은 400.
- robots.txt: SEO 설정의 robots.txt(비면 전체 허용 + 사이트맵) 뒤에 허용 · 차단 크롤러 규칙을 더한다. SEO robots.txt 에 이미 그 User-agent 규칙이 있으면 더하지 않고 화면에 경고 (단일 규칙 저장소 = SEO robots.txt). 화면에 예상 결과 미리보기. 연결한 도메인에서만 적용된다.
- 홈페이지 사업체 JSON-LD: `description` = 기업 소개 (없으면 SEO 메타 설명), `knowsAbout` = 주제, `sameAs` = SNS 주소 + 공식 프로필 (중복 제거).
- API: `GET /api/v1/seo-settings/geo` → `{settings, crawlers: [{name, label}]}` · `PUT` 은 `settings` 그대로. 공개 응답 `seo_settings.geo` 는 출처 목록을 뺀 `{description, topics, profile_urls, crawlers}`.
- 저장: `seo_settings.geo` JSONB (마이그레이션 0058).
- 성과 점수 · 인용률 같은 근거 없는 지표는 보여 주지 않는다. 검색 노출 · AI 인용을 보장하지 않는다는 안내를 둔다.

## 8. SEO 설정 보완 (SM-04, T-225 ✅)

- **저장:** 탭(기본 SEO · 소셜 미리보기 · 사이트맵 · 분석 연동)별 저장 버튼을 없애고 공통 저장 막대 하나로 한꺼번에 저장. 탭을 옮겨도 고친 내용은 남는다. 화면 이름은 'SEO 설정'.
- **검색 결과 미리보기:** 주소는 대표 주소 → 연결한 도메인 → 기본 주소(`/{slug}`). 제목이 비면 사업체 이름이 나간다고, 설명이 비면 검색엔진이 본문에서 고른다고 알린다. 제목 60자 · 설명 160자를 넘으면 잘린 모습과 안내. 검색 노출을 끄면(noindex) 흐리게 보이고 안내.
- **사이트맵:** 안내 주소는 홈페이지가 만드는 실제 사이트맵 — 기본 `/{slug}/sitemap.xml`, 연결한 도메인은 `https://도메인/sitemap.xml`. [생성 결과 확인]은 기본 주소를 불러와 주소 수(메인 · 페이지 · 게시판 / 글)와 목록(200개까지)을 보여 준다. 홈페이지 사이트맵 응답에 `Access-Control-Allow-Origin: *` (공개 문서).
- **robots.txt:** [규칙 보기]로 연결한 도메인에서 나가는 최종 결과(SEO robots.txt, 비면 전체 허용 + 사이트맵, 뒤에 GEO 크롤러 규칙)를 미리 본다.
- 예전 백엔드 사이트맵 주소 `GET /api/public/sitemap/{slug}.xml` 은 홈 주소 한 줄만 있던 결과 대신 홈페이지 사이트맵으로 307 (없는 사업체는 404).
