## 0. 배포 차단 문제와 처리 상태

2026-10-27 점검에서 발견한 문제. **B1 ~ B4 는 수정 완료**(브랜치 `fix/deploy-config`), B5 는 🧑 결정 필요.

| # | 문제 (수정 전) | 영향 | 처리 |
|---|---|---|---|
| B1 | **프론트 3개 앱 빌드에 API 주소가 안 들어간다** — `NEXT_PUBLIC_*` · `VITE_*` 는 빌드 때 고정되는데 Dockerfile 에 `ARG` 가 없고 `.env*` 는 `.dockerignore` 로 제외 | 홈페이지 · 관리자 · 슈퍼 어드민이 `http://localhost:8000` 을 호출 → 전부 실패 | ✅ Dockerfile `ARG`→`ENV`, compose `build.args` 를 루트 `.env` 의 `PUBLIC_DOMAIN` 으로 생성 (없으면 빌드 거부). 홈페이지 서버 렌더링 · 미들웨어는 `API_INTERNAL_URL=http://backend:8000/api` 로 내부 호출 |
| B2 | **운영 compose 의 백엔드 환경변수가 일부만 전달된다** (DB · Redis · MinIO · 시크릿 · OpenAI 만) | `APP_ENV` 가 기본값 `development` → Swagger(`/docs`) 공개, **휴대폰 인증번호가 응답에 노출**(`debug_code`). `ALLOWED_ORIGINS` · `COOKIE_DOMAIN` · `CDN_BASE_URL` · 결제 · 메일 · 알림 · 소셜 설정 모두 개발 기본값 | ✅ backend · worker · beat 가 `apps/backend/.env.production` 을 읽음 (`.env.production.example` 제공). **`APP_ENV=production` 인데 개발 기본값이 남으면 백엔드가 기동하지 않음** (`config.production_problems`, 예외는 `PRODUCTION_CHECK_SKIP`) |
| B3 | **업로드 이미지가 외부에서 안 보인다** — MinIO 가 내부 네트워크에만 있고 nginx 에 이미지 경로가 없음 | 고객이 올린 이미지 · 템플릿 샘플 이미지 표시 불가 | ✅ nginx `/cms-media/` → MinIO (읽기만), MinIO 를 nginx 와 같은 네트워크에 (호스트 포트는 닫힘). `CDN_BASE_URL=https://도메인/cms-media` |
| B4 | **백엔드 이미지에 `scripts/` 가 없다** (Dockerfile 이 `app` · `alembic` 만 복사) | 운영 컨테이너에서 `init_db_roles.py` · `init_minio.py` · `seed.py` 실행 불가 | ✅ 백엔드 이미지에 `scripts/` 포함 (`.dockerignore` 에서 제외돼 있었음), `PYTHONPATH=/app` |
| B5 | **DB 백업이 없다** — 백업 스크립트 · 일정 없음 | 장애 · 실수 시 데이터 복구 불가 | `pg_dump` 일일 백업 + MinIO 데이터 백업, 보관 기간 정하기 |

> B5 는 백업 위치(서버 디스크 · S3 등)와 보관 기간을 🧑 결정해야 한다.

## 2. 운영 환경변수

### 2.1 루트 `.env` (docker compose 용) 🔧

| 변수 | 값 |
|---|---|
| `PUBLIC_DOMAIN` | 대표 도메인 (예: `cms.kr`) — 프론트 빌드 주소를 만든다 (`admin.` · `system.` 자동) |
| `CDN_HOSTNAME` (선택) | 이미지 호스트가 따로 있을 때 (기본 `PUBLIC_DOMAIN`) |
| `RECAPTCHA_SITE_KEY` · `KAKAO_MAP_API_KEY` · `ADMIN_SENTRY_DSN` | 프론트 빌드에 들어갈 공개 키 (선택이지만 reCAPTCHA 는 권장) |
| `POSTGRES_DB` · `POSTGRES_USER` · `POSTGRES_PASSWORD` | DB 소유자 계정 (강한 비밀번호) |
| `APP_DB_USER` · `APP_DB_PASSWORD` | **앱 전용 계정** (기본 `cms_app`, 강한 비밀번호) — RLS 적용 |
| `REDIS_PASSWORD` | 강한 비밀번호 |
| `MINIO_ROOT_USER` · `MINIO_ROOT_PASSWORD` | 강한 값 |
| `APP_SECRET_KEY` | **32자 이상 무작위** (짧으면 기동 실패) |
| `OPENAI_API_KEY` | 1절 |

### 2.2 백엔드 (`apps/backend/.env.production`) 🔧

`cp apps/backend/.env.production.example apps/backend/.env.production` 후 채운다. 아래 값이 개발 기본값이면 **백엔드가 기동하지 않고 항목을 알려준다.**

**반드시 바꿀 값** (개발 기본값 그대로 두면 위험)

| 변수 | 운영 값 | 이유 |
|---|---|---|
| `APP_ENV` | `production` | Swagger 비공개, 인증번호 · 재설정 링크 디버그 노출 차단 |
| `ALLOWED_ORIGINS` | `https://도메인,https://admin.도메인,https://system.도메인` | CORS |
| `COOKIE_DOMAIN` | `.도메인` (점으로 시작) | 홈페이지 ↔ 관리자 로그인 공유 (CLAUDE.md 7.2) |
| `ADMIN_BASE_URL` · `CLIENT_BASE_URL` | `https://admin.도메인` · `https://도메인` | 메일 · 알림 링크 |
| `CDN_BASE_URL` | B3 의 이미지 공개 주소 (예: `https://도메인/cms-media`) | 업로드 이미지 주소 |
| `MINIO_USE_SSL` | 구성에 맞게 | |
| `SUPER_ADMIN_EMAIL` · `SUPER_ADMIN_PASSWORD` | 실제 운영 계정 | 시드가 만드는 최초 슈퍼 어드민 |
| `SUPER_ADMIN_ALLOWED_IPS` | 사무실 IP 목록 (권장) | 슈퍼 어드민 접근 제한 |
| `NOTIFICATION_MODE` | `live` | 실제 알림톡 · SMS 발송 (test 면 발송 안 함 + 디버그 노출) |
| `EMAIL_MODE` · `PAYMENT_MODE` · `DOMAIN_MODE` · `SOCIAL_MODE` | `live` | 각각 실제 연동 |
| `SOCIAL_REDIRECT_URI` | `https://도메인/member/social/callback` | 카카오 · 네이버 등록 주소와 같아야 함 |
| `DOMAIN_CNAME_TARGET` | 운영 대표 도메인 | 커스텀 도메인 안내 |
| `RECAPTCHA_SECRET_KEY` | 1절 | 비우면 검증 없이 통과 |
| `BILLING_KEY_ENCRYPTION_KEY` | base64 32바이트 (권장 — 비우면 `APP_SECRET_KEY` 에서 파생) | 빌링키 암호화. **바꾸면 기존 빌링키 복호화 불가** |
| `TEMPLATE_ASSET_BASE_URL` | 처음엔 비움 → 3절 9단계 후 `CDN_BASE_URL` 과 같은 값 | 샘플 이미지 공용 주소 |
| `SENTRY_DSN` · `SENTRY_ENVIRONMENT=production` | 선택 | |

`DATABASE_URL` · `MIGRATION_DATABASE_URL` · `REDIS_URL` 등 접속 주소는 `docker-compose.prod.yml` 이 2.1 값으로 만든다.

## 3. 최초 배포 순서 🔧

> 2절 환경변수를 채운 상태에서. 명령은 저장소 루트에서.

| 단계 | 명령 · 작업 | 확인 |
|---|---|---|
| 1 | DNS A 레코드 4개가 서버 IP 를 가리킴 | `dig 도메인` |
| 2 | `nginx/nginx.conf` 의 `cms.example.com` 을 실제 도메인으로 일괄 치환 | |
| 3 | 인프라 기동: `docker compose -f docker-compose.prod.yml up -d postgres redis minio` | healthy |
| 4 | 이미지 빌드: `docker compose -f docker-compose.prod.yml build` | 빌드 성공 |
| 5 | **DB 마이그레이션**: `docker compose -f docker-compose.prod.yml run --rm backend alembic upgrade head` | `alembic current` = `0024 (head)` |
| 6 | **앱 DB 계정**: `… run --rm backend python scripts/init_db_roles.py` | "일반 권한 · RLS 적용" 출력 |
| 7 | **이미지 버킷**: `… run --rm backend python scripts/init_minio.py` | "공개 읽기 정책 적용" 출력 |
| 8 | **초기 데이터**: `… run --rm backend python scripts/seed.py` | 슈퍼 어드민 · 템플릿 생성 (데모 테넌트 · 회원 시드는 운영에서 지울지 🧑 결정) |
| 9 | **샘플 이미지 업로드** (출처 확인 후) — 홈페이지 폴더의 이미지가 필요해 컨테이너가 아닌 **저장소 체크아웃에서** MinIO 에 접근 가능한 곳에서 `python scripts/upload_template_assets.py` → `.env.production` 의 `TEMPLATE_ASSET_BASE_URL` 설정 후 backend 재시작 | 업로드 개수 출력 |
| 10 | 앱 기동: `docker compose -f docker-compose.prod.yml up -d` | 모든 컨테이너 Up |
| 11 | SSL 최초 발급 (`nginx/README.md` 절차) → `nginx -s reload` | `https://` 접속 |
| 12 | 모니터링 (선택): `docker compose -f docker-compose.monitoring.yml up -d` | Grafana 접속 |

## 4. 배포 후 확인 (스모크 테스트) 🔧

**보안 설정**
- [ ] `https://도메인/api/v1/sections` → 401 `{"success": false, "error": {"code": "UNAUTHORIZED", …}}`
- [ ] `https://도메인/docs` → 404 (`APP_ENV=production` 이면 Swagger 비공개)
- [ ] DB 에서 앱 접속 계정 확인: `SELECT usename FROM pg_stat_activity WHERE datname = '…'` → `cms_app` (소유자 계정이면 RLS 꺼짐)
- [ ] 휴대폰 인증번호 요청 응답에 `debug_code` 가 **없음**
- [ ] HTTP → HTTPS 리다이렉트, HSTS 헤더

**기능**
- [ ] 슈퍼 어드민(`system.`) 로그인 → 테넌트 생성 (시작 템플릿 선택)
- [ ] 관리자(`admin.`) 로그인 → 섹션 수정 → 홈페이지 반영
- [ ] 이미지 업로드 → 홈페이지에 이미지 표시 (`https://도메인/cms-media/…` 200)
- [ ] `https://도메인/cms-media/` (버킷 목록) → 403, `PUT`/`DELETE` → 403
- [ ] 홈페이지에서 관리자 로그인 → 편집 모드 (쿠키 공유, `COOKIE_DOMAIN`)
- [ ] 문의 접수 → 관리자 목록 · 알림톡/이메일 수신
- [ ] 방문자 회원가입 (실제 SMS 인증번호) → 마이페이지 → 탈퇴
- [ ] 카카오 · 네이버 로그인
- [ ] 결제 카드 등록 (토스 실결제 소액 확인 후 취소)
- [ ] 커스텀 도메인 연결 (선택)
- [ ] 모바일 PageSpeed Insights 재측정 (T-125 — 로컬 측정은 84 ~ 95 로 흔들림)

## 5. 운영 중 정기 작업 🔧

| 주기 | 작업 |
|---|---|
| 매일 | DB 백업 (B5) — `pg_dump` 를 서버 밖(S3 등)으로, 보관 기간 🧑 결정 |
| 매일 | MinIO 데이터 백업 (업로드 이미지) |
| 12시간 | certbot 자동 갱신 (compose 포함) → 갱신 후 `nginx -s reload` (cron 또는 `--deploy-hook` 권장) |
| 매 배포 | 새 마이그레이션이 있으면 `alembic upgrade head` → 새 테이블에도 앱 계정 권한은 자동 부여 (default privileges) |
| 매 배포 | 템플릿 이미지를 바꿨으면 `upload_template_assets.py` (새 버전 폴더) |
| 수시 | Sentry · Grafana 오류 · 지연 확인 |
| 분기 | 백업 복원 리허설 |

**롤백**
- 앱: 이전 이미지 태그로 `docker compose … up -d` (ECS 는 이전 태스크 정의)
- DB: `alembic downgrade -1` (마이그레이션마다 되돌리기 검토 필요) 또는 백업 복원
- 템플릿 적용 실수는 관리자 화면에서 7일 내 롤백 가능 (기획서 11.8)

## 6. ECS 배포 (`.github/workflows/deploy.yml`) 를 쓸 경우

- 저장소 변수 `DEPLOY_ENABLED=true` 일 때 main 테스트 통과 후 자동 배포 (ECR 이미지 → ECS 서비스 재배포)
- 필요한 Secrets: `AWS_REGION`, `ECR_REGISTRY`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `ECS_CLUSTER`
- **마이그레이션 단계가 워크플로에 없다** → 배포 전 `alembic upgrade head` 를 별도 태스크로 실행하는 단계 추가 필요 🛠
- 프론트 빌드 값: 저장소 **Variables** 에 `PUBLIC_DOMAIN`(필수) · `CDN_HOSTNAME` · `RECAPTCHA_SITE_KEY` · `KAKAO_MAP_API_KEY` · `ADMIN_SENTRY_DSN` — 워크플로가 `build-args` 로 넘긴다 (B1 ✅)
- 백엔드 환경변수: ECS 태스크 정의(또는 Secrets Manager)에 2.2 값 전부, 홈페이지 태스크에 `API_INTERNAL_URL`(내부 백엔드 주소)
