# 스타트업·중소기업 홈페이지 디자인 템플릿 기획서

- 문서 버전: v0.1 — 검토용 초안
- 작성일: 2026-11-05
- 가칭: **Corporate A · 코퍼레이트 A**
- 템플릿 키 제안: `corporate-a` / ID 제안: `TPL_CORPORATE_A`
- 적용 대상: 현재 개발 중인 멀티 테넌트 CMS
- 상태: 디자인 방향·페이지 구성 제안. 개발 범위와 일정은 미확정.

> 본 문서는 새 템플릿의 화면과 콘텐츠를 기획한 초안이다. 기존 CMS에 구현된 기능과 신규 연동이 필요한 항목을 구분하며, 기존 전체 기획서나 TASK.md의 확정 범위를 변경하지 않는다.

## 1. 기획 목적

스타트업과 중소기업이 전문 디자이너 없이도 자사의 사업, 강점, 수행 사례를 설득력 있게 소개하고 고객 문의를 받을 수 있는 기업 홈페이지 템플릿을 만든다.

방문자가 다음 세 가지 질문에 순서대로 답을 얻도록 설계한다.

1. 어떤 일을 하는 회사인가?
2. 우리 문제를 해결할 역량과 근거가 있는가?
3. 어떻게 상담하거나 협업을 제안할 수 있는가?

사이트의 주 행동은 **프로젝트·서비스 문의**, 보조 행동은 **사업영역 확인**으로 설정한다. 첫 화면부터 회사의 사업을 이해할 수 있어야 하며, 추상적인 슬로건만 제시하지 않는다.

## 2. 대상 기업과 방문자

| 구분 | 주요 요구 | 템플릿 대응 |
|---|---|---|
| 초기 스타트업 | 짧은 회사 이력, 적은 이미지로도 완성된 홈페이지 필요 | 실적·연혁을 숨겨도 자연스러운 구성, 서비스 설명과 강점 중심 |
| IT·솔루션 기업 | 제품 가치와 도입 효과 설명 | 서비스 소개, 화면 이미지, 도입 과정, 문의 연결 |
| 전문 서비스·B2B 기업 | 수행 역량과 사례를 통한 신뢰 형성 | 프로젝트 사례, 전문 분야, 협업 절차 |
| 제조·기술 중소기업 | 기술력·시설·인증·연혁 소개 | 사업 이미지와 기술 설명, 선택형 인증·연혁 영역 |

주요 방문자는 도입을 검토하는 기업 담당자, 협력사 담당자, 회사 정보를 확인하는 잠재 고객이다. 구직자·투자자를 위한 정보는 회사소개에서 보조적으로 제공한다.

**범위 가정:** 이번 템플릿은 기업 소개와 문의 확보가 중심이다. 쇼핑몰, 회원 전용 서비스, 복잡한 제품 카탈로그는 별도 기획 대상으로 둔다.

## 3. 디자인 콘셉트

### 3.1 핵심 방향

**“명확한 사업 설명과 정돈된 신뢰감.”**

넓은 여백, 큰 제목, 간결한 문장과 실제 사업 이미지를 조합한다. 스타트업에는 가볍고 현대적인 인상을, 중소기업에는 안정적인 기업 이미지를 줄 수 있도록 기본은 밝고 차분하게 설계한다.

- 기본 화면: 화이트와 옅은 회색 배경, 진한 네이비 텍스트, 블루 포인트.
- 첫 화면: 왼쪽에 사업 설명과 버튼, 오른쪽에 대표 이미지 또는 제품 화면.
- 시각적 리듬: 이미지·텍스트 분할, 카드, 넓은 배너를 번갈아 사용한다.
- 카드: 서비스와 사례처럼 비교가 필요한 콘텐츠에 사용한다.
- 사진이 부족한 기업: 제품 화면, 단색 배경과 타이포그래피로 대체 가능하게 한다.
- 움직임: 짧은 등장 효과와 버튼 반응 수준으로 제한한다. 움직임 없이도 모든 정보를 이해할 수 있어야 한다.

### 3.2 기본 디자인 값 제안

| 요소 | 초안 기준 |
|---|---|
| 주요 색상 | 블루 `#2563EB` |
| 기본 본문색 | 네이비 `#0F172A` |
| 보조 본문색 | 슬레이트 `#475569` |
| 배경 / 보조 배경 | `#FFFFFF` / `#F8FAFC` |
| 글꼴 | CMS 공통 Noto Sans KR, 시스템 대체 글꼴 |
| 본문 크기 | PC 16~18px, 모바일 16px 기준 |
| 메인 제목 | PC 56~64px, 모바일 32~40px 범위에서 조정 |
| 본문 최대 폭 | 1,200px 제안 |
| 섹션 상하 간격 | PC 96~120px, 모바일 56~72px |
| 모서리 | 버튼 8px, 카드 12~16px |

위 수치는 시안용 제안이며 브랜드 색상 변경을 허용한다. 색상 변경 시 버튼 글자와 배경의 가독성을 함께 확인한다. 초기 버전은 라이트 모드 한 가지로 제작한다.

## 4. 사이트 구조

기본은 메인과 서브 페이지를 함께 갖는 기업 홈페이지다. 내용이 적은 고객은 선택 페이지를 메뉴에서 숨겨 더 간결하게 운영할 수 있다.

| 페이지 | 페이지 키 제안 | 역할 | 기본 상태 |
|---|---|---|---|
| 홈 | `home` | 사업 이해 → 근거 확인 → 문의 유도 | 기본 |
| 회사소개 | `about` | 비전·회사 개요·핵심 가치·연혁 | 기본 |
| 사업영역 | `business` | 서비스·솔루션의 대상과 제공 가치 설명 | 기본 |
| 프로젝트 | `projects` | 실제 수행 사례와 결과 소개 | 선택 |
| 소식 | `notice` | 공지·기업 활동·업데이트 안내 | 선택 |
| 문의하기 | `contact` | 문의 접수와 연락처 안내 | 기본 |
| 개인정보처리방침 | 경로는 기존 정책 확인 후 결정 | 사이트 운영 정책 안내 | 푸터 연결 |

프로젝트 상세는 사례 수와 관리 방식에 따라 후속 범위를 결정한다. 초기 디자인에서는 목록과 상세 시안을 준비하되, 공개 기능으로 포함할지는 CMS 연동 확인 후 확정한다.

상단 메뉴는 로고, 회사소개, 사업영역, 프로젝트, 소식, 문의하기 버튼으로 구성한다. 홈 이동은 로고로 제공한다. 숨긴 페이지는 메뉴와 관련 바로가기에서도 함께 제외한다.

## 5. 메인 페이지 상세 기획

### 5.1 화면 흐름

`헤더 → 히어로 → 신뢰 근거 → 사업영역 → 차별점 → 프로젝트 → 회사소개 → 소식 → 문의 배너 → 푸터`

신뢰 근거·프로젝트·소식이 없는 고객은 해당 영역을 숨긴다. 숨긴 뒤에도 사업 소개에서 문의까지 흐름이 이어져야 한다.

| 영역 | 목적과 구성 | 편집 콘텐츠 | 이동·동작 |
|---|---|---|---|
| 헤더 | 로고, 주요 메뉴, 문의 버튼 | 로고, 메뉴명·노출·순서 | 스크롤 시 상단 고정, 모바일 메뉴 제공 |
| 히어로 | 업종 보조 문구, 핵심 제목, 설명, 버튼 2개, 대표 이미지 | 문구, 이미지, 버튼명·목적지 | 주 버튼은 문의, 보조 버튼은 사업영역 |
| 신뢰 근거 | 고객·파트너 로고 또는 주요 지표 | 로고, 지표명·수치·기준 설명 | 선택 영역, 자동 순환 없이 정적 배치 |
| 사업영역 | 섹션 제목과 서비스 카드 3개 기본 | 제목, 설명, 이미지 또는 아이콘 | 사업영역 페이지의 해당 항목으로 연결 |
| 차별점 | 이미지와 핵심 강점 3개 기본 | 강점 제목·설명, 이미지 | 짧은 문장으로 선택 이유 전달 |
| 프로젝트 | 대표 사례 카드 3개 기본 | 대표 이미지, 분야, 제목, 요약 | 상세가 제공되면 상세 이동, 아니면 프로젝트 페이지 |
| 회사소개 | 회사의 방향과 일하는 방식 요약 | 제목, 설명, 이미지 | 회사소개로 이동 |
| 소식 | 최신 글 3개 기본, 제목·날짜·분류 | 게시판 데이터 연동 제안 | 목록·상세로 이동 |
| 문의 배너 | 행동을 유도하는 문구와 버튼 | 제목, 설명, 버튼 | 문의하기로 이동 |
| 푸터 | 회사 정보, 연락처, 정책 링크, 저작권 | CMS 공통 사업체 정보 중심 | 이메일·전화·정책 링크 |

### 5.2 히어로 예시

- 보조 문구: “기업의 디지털 업무 파트너”
- 제목: “복잡한 업무를 줄이고,\n성장에 집중할 수 있도록.”
- 설명: “업무 시스템 구축부터 운영 개선까지, 우리 회사에 맞는 디지털 솔루션을 제공합니다.”
- 주 버튼: “프로젝트 문의하기”
- 보조 버튼: “서비스 살펴보기”
- 비주얼: 제품 화면 또는 실제 업무·기술 이미지. 과장된 장식보다 사업 이해를 돕는 이미지를 사용한다.

모든 예시는 가상 기업을 위한 샘플이다. 실제 고객사·실적·인증을 암시하는 임의의 수치는 넣지 않는다.

### 5.3 콘텐츠 길이와 수량

- 히어로 제목은 PC 2~3줄, 모바일 3~4줄을 권장한다. 한글 단어가 부자연스럽게 끊기지 않도록 한다.
- 설명은 PC 2~3줄을 권장하되 긴 문구는 잘라 숨기지 않고 영역 높이가 늘어나게 한다.
- 사업 카드 기본 3개, 허용 수량 제안 1~6개. 1~2개일 때도 균형을 유지한다.
- 로고·지표·사례가 없으면 해당 섹션을 숨길 수 있다. 임의 샘플로 자동 보충하지 않는다.
- 카드 전체가 링크이면 같은 카드 안에 중복된 링크 버튼을 만들지 않는다.

## 6. 서브 페이지 상세 기획

### 6.1 회사소개

구성: 서브 타이틀 → 회사 소개문·대표 이미지 → 미션과 비전 → 핵심 가치 → 회사 개요 → 선택형 연혁·인증 → 문의 배너.

- 회사 개요: 회사명, 설립연도, 주요 사업, 소재지 등 공개 가능한 항목.
- 핵심 가치: 기본 3개, 제목과 짧은 설명.
- 연혁: 연도별 주요 사건을 시간순으로 제공한다. 설립 초기 회사는 숨길 수 있다.
- 인증: 실제 인증 이미지와 명칭이 있을 때만 표시한다.
- 대표 인사말과 조직도는 초기 필수 항목에서 제외한다.

### 6.2 사업영역

구성: 서브 타이틀 → 사업 요약 → 서비스별 이미지·설명 → 제공 항목 → 진행 과정 → 문의 배너.

서비스는 “대상 고객 → 해결할 문제 → 제공 내용 → 기대 효과” 순서로 설명한다. 기본 3개 사업을 한 페이지에서 소개하고, 초기 버전에는 서비스별 별도 상세 페이지를 만들지 않는다.

진행 과정 예시: 문의 접수 → 요구사항 확인 → 제안·협의 → 진행·납품. 회사가 실제로 운영하는 단계와 용어로 바꿀 수 있게 한다.

### 6.3 프로젝트 — 선택

목록은 이미지 카드 그리드로 구성한다. 카드에는 분야, 프로젝트명, 요약을 표시한다. 분류 필터와 페이지 이동은 실제 데이터 관리 기능이 지원되는 경우에 포함한다.

상세 시안에는 대표 이미지, 프로젝트 개요, 수행 범위, 해결 과정, 결과 이미지, 관련 문의 버튼을 포함한다. 고객명·수행 기간·성과 수치는 선택 항목이며 공개할 수 없는 정보는 숨긴다.

프로젝트가 0건이면 공개 메뉴와 메인 사례 섹션을 기본 숨김 처리하는 방향으로 설계한다. 직접 주소 접근 시에는 빈 상태 안내와 문의 또는 사업영역 링크를 제공한다.

### 6.4 소식 — 선택

목록: 상단 제목 → 공지 목록 → 검색·페이지 이동. 상세: 제목 → 날짜 → 본문·이미지 → 목록 돌아가기.

기존 공지 게시판과의 연동을 우선 검토한다. 새 게시판을 만드는 기능과 템플릿에서 실제로 표시하는 기능은 구분한다. 글이 없으면 메인 최신 소식은 숨기고, 목록에는 “등록된 소식이 없습니다”를 표시한다.

### 6.5 문의하기

구성: 안내 제목 → 문의 폼과 연락처 → 선택형 위치 안내.

| 항목 | 필수 여부 제안 | 입력 형태 |
|---|---|---|
| 문의 유형 | 선택 | 서비스 문의 / 프로젝트 문의 / 제휴 / 기타 |
| 회사명 | 선택 | 텍스트 |
| 담당자명 | 필수 | 텍스트 |
| 이메일 | 필수 | 이메일 |
| 연락처 | 선택 | 전화번호 |
| 문의 내용 | 필수 | 여러 줄 텍스트 |
| 개인정보 수집·이용 동의 | 필수 | 동의 내용 확인과 체크 |

필드는 현재 문의 API·관리자 필드 설정과 대조해 최종 확정한다. 위 표는 화면 요구사항이며 현재 전부 지원된다는 의미는 아니다.

- 제출 중에는 중복 제출을 막고 진행 상태를 표시한다.
- 성공 시 “문의가 접수되었습니다. 확인 후 남겨주신 연락처로 안내드리겠습니다.”를 표시한다.
- 실패 시 입력 내용을 유지하고 재시도 방법을 안내한다.
- 오류는 해당 입력칸 아래에 표시하며 색상 외에 텍스트로도 구분한다.
- 이메일·전화는 실제 연락 동작으로 연결한다. 지도는 설정이 있을 때 표시하며 없으면 주소 텍스트만 제공한다.
- 파일 첨부, 외부 CRM 전송, 채팅 상담은 초기 범위에서 제외한다.

## 7. 공통 UI와 반응형

| 항목 | PC | 모바일 |
|---|---|---|
| 헤더 | 로고·메뉴·문의 버튼 가로 배치 | 로고·메뉴 버튼, 펼침 메뉴 |
| 히어로 | 텍스트·이미지 2열 | 텍스트 → 버튼 → 이미지 순서 |
| 카드 | 3열 기본, 수량에 따라 조정 | 1열 기본, 로고 묶음은 2열 가능 |
| 이미지·텍스트 | 좌우 분할 | 제목·설명과 이미지의 읽는 순서 유지 |
| 문의 폼 | 폼과 연락처 2열 | 1열, 입력칸 가로 폭 확보 |
| 푸터 | 회사 정보와 링크를 분리 배치 | 세로 배치 |

- 모바일 메뉴는 열기·닫기와 현재 페이지를 명확히 표시한다. 키보드와 터치로 조작할 수 있어야 한다.
- 390px와 1440px를 주요 검토 폭으로 사용하고 360px·768px·1920px에서도 내용 손실과 가로 넘침을 확인한다.
- 이미지 비율 제안: 히어로 4:3, 프로젝트 16:10. 초점 위치를 고려하고 로고는 잘라내지 않는다.
- 주요 버튼 높이는 48px를 기준으로 한다. 키보드 포커스 표시와 이미지 대체 설명을 제공한다.
- 첫 화면 자동 슬라이드·배경 영상·필수 로딩 애니메이션은 사용하지 않는다.
- 문의 버튼의 목적지와 메뉴 이동은 고객 도메인과 템플릿 미리보기에서도 일관되어야 한다.

## 8. CMS 편집 범위와 연동 원칙

### 8.1 고객이 편집할 내용

- 회사명, 로고, 연락처, 주소 등 공통 정보.
- 지원하는 색상·글꼴 설정과 메뉴명·노출·순서.
- 섹션 제목, 본문, 이미지, 카드 항목, 버튼명·목적지.
- 선택 섹션의 표시 여부와 지원 범위 안의 순서.
- 공지 게시글과 접수된 문의는 기존 관리 화면에서 운영한다.

레이아웃 비율, 모바일 전환 규칙, 글자 크기 체계는 템플릿에서 관리한다. 임의 HTML/CSS 입력과 자유로운 페이지 생성은 이번 디자인의 편집 범위에 포함하지 않는다.

### 8.2 기존 구조에 맞출 항목

- 독립적인 레이아웃을 갖는 **코드형 템플릿**을 제안한다. 스타일 작성 방식은 구현 단계에서 확정한다.
- 기존 템플릿 매니페스트, 페이지·섹션 데이터, 공통 편집 컴포넌트를 사용한다.
- 브랜드 색상과 폰트는 기존 CMS 토큰으로 연결하고 스타일은 템플릿 범위 안에 격리한다.
- 템플릿 변경 시 기존 콘텐츠를 보존하는 정책을 따른다. 표시하지 못하는 섹션도 임의로 삭제하지 않는다.
- 샘플 콘텐츠는 신규 적용용으로 준비하고 기존 고객 콘텐츠와 혼동되지 않게 관리한다.

### 8.3 구현 전 확인할 차이

| 화면 요구 | 현재 확인한 기반 | 추가 확인·작업 |
|---|---|---|
| 회사·사업 소개 | 코드형 페이지와 콘텐츠 블록 구조 존재 | 신규 레이아웃과 편집 필드 매핑 |
| 신뢰 지표·고객사 로고 | 콘텐츠 블록 활용 가능성 | 목록 편집과 숨김 정책 검토 |
| 공지·최신 소식 | 기존 템플릿에 공지 연동 기반 존재 | 새 템플릿에 화면·메뉴·데이터 연결 |
| 프로젝트 목록·상세 | 게시판 생성은 TASK.md상 완료 | 공개 게시판 화면은 T-140-B가 미완료이므로 의존성 확인 |
| 기업 문의 폼 | 기존 문의 시스템 존재 | 문의 유형·필드·저장·관리자 표시 대조 |
| 개인정보처리방침 | 푸터 정책 링크 필요 | 기존 정책 제공 방식과 경로 확인 |

프로젝트 기능은 디자인 제작과 별개로 범위를 결정한다. 초기에는 편집 가능한 사례 소개 섹션으로 제공하고, 게시판 연동이 준비되면 목록·상세로 확장하는 방안도 가능하다.

## 9. 샘플 콘텐츠와 이미지 준비

- 가상 기업명: “넥스트웨이브” — 작업용 이름이며 공개 전 명칭 검토.
- 가상 업종: 기업용 디지털 솔루션·업무 시스템 구축.
- 샘플 사업: 업무 시스템 구축 / 데이터 활용 / 서비스 운영 개선.
- 샘플 사례: 가상의 업무 개선 사례 3개. 실제 기업 로고나 실제 성과처럼 표현하지 않는다.
- 이미지: 히어로 1장, 회사소개 1~2장, 사업영역 3장, 사례 대표 이미지 최대 3장.
- 회사 이미지가 없어도 사용할 수 있는 타이포그래피 중심 대체 구성을 준비한다.
- 샘플 이미지의 출처와 이용 조건을 기록하고 고객별 이미지와 구분해 보관한다.

## 10. 첫 버전 범위

**기본 제공 제안:** 공통 헤더·푸터, 홈, 회사소개, 사업영역, 문의하기, 반응형, CMS 편집 연결, 샘플 콘텐츠.

**선택 제공 제안:** 프로젝트, 소식, 연혁, 인증, 고객사 로고, 실적 지표. 실제 콘텐츠와 기능 연동이 준비된 항목만 공개한다.

**후속 검토:** 채용 게시판, 다국어, 다운로드형 회사소개서, 제품별 상세, 외부 CRM 연동, 고급 분류·검색. 초기 버전에는 포함하지 않는다.

## 11. 제작 순서와 산출물

1. **기획 정리:** 디자인 방향, 기본·선택 페이지, 프로젝트 운영 방식 확정.
2. **와이어프레임:** PC·모바일 메인과 문의 화면, 서브 페이지 공통 구조.
3. **디자인 시안:** 메인과 공통 UI를 먼저 만들고 서브 페이지로 확장.
4. **목업:** 기본 페이지와 선택 페이지의 PC·모바일 화면, 빈 상태·오류·완료 상태.
5. **CMS 이식:** 데이터·편집 연결과 샘플 구성, 메뉴·도메인·미리보기 검증.

최종 산출물은 페이지별 디자인, 공통 컴포넌트 기준, 편집 항목표, 샘플 콘텐츠·이미지 목록, 검수 결과다. 일정은 페이지와 연동 범위를 정한 뒤 산정한다.

## 12. 검수 기준

- 첫 화면에서 어떤 고객에게 무엇을 제공하는 회사인지 설명할 수 있다.
- 홈과 사업영역에서 문의 페이지까지 자연스럽게 이동할 수 있다.
- 로고·지표·사례가 없는 초기 기업도 빈 공간이나 가짜 실적 없이 사용할 수 있다.
- 짧은 문구·긴 문구, 카드 1개·3개·6개, 이미지 없음 상태에서 레이아웃이 유지된다.
- 모바일에서 메뉴·본문·문의 폼에 가로 넘침이 없다.
- 고객이 바꾼 문구·이미지·색상·메뉴 설정이 공개 화면과 미리보기에 반영된다.
- 문의 성공·실패·검증 오류 상태를 확인하고 접수 내용이 관리자에 표시된다.
- 선택 페이지를 숨기면 메인 연결 링크와 메뉴도 일관되게 처리된다.
- 고객 도메인, 기본 테넌트 주소, 템플릿 미리보기의 이동을 확인한다.

## 13. 검토할 결정 사항

| 결정 사항 | 초안 제안 |
|---|---|
| 우선 대상 | IT·B2B 서비스 기업 중심으로 시작하고 제조·기술 기업도 이미지 교체로 수용 |
| 디자인 인상 | 밝고 정돈된 기업형, 블루 포인트 |
| 페이지 구성 | 기본 4개 + 선택 2개 + 정책 링크 |
| 메인 비주얼 | 텍스트·이미지 분할, 자동 슬라이드 없음 |
| 프로젝트 관리 | 초기 사례 섹션과 게시판 연동 중 구현 준비 상태에 맞춰 선택 |
| 회원가입·예약 | 기본 메뉴와 첫 버전 범위에서 제외 |

이 초안을 바탕으로 메인 와이어프레임을 작성한 뒤, 실제 콘텐츠를 배치해 정보량과 디자인 방향을 검토한다.
