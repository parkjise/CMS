## 5. 배포 (Deploy) 활성화 방법

기본은 **비활성(skip)**. 실제 AWS 배포를 켜려면:
1. GitHub → Settings → Secrets and variables → Actions → **Secrets**:
   `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, `ECR_REGISTRY`, `ECS_CLUSTER`
2. 같은 화면 **Variables** 탭: `DEPLOY_ENABLED = true`
3. 이후 Test 성공 시 → 4개 이미지 빌드 → ECR → ECS 자동 배포
> 자세한 내용: `.github/workflows/README.md`

## 6. main 브랜치 보호 & PR 워크플로

### 현재 보호 설정
- 필수 상태 체크: `backend`, `frontend` (통과해야 머지 가능)
- `enforce_admins: true` → **관리자 포함 누구도 main 직접 push 불가**
- `strict: true` → PR은 main 최신 반영 후 머지

### 확인 (웹)
`https://github.com/parkjise/CMS/settings/branches` → main 규칙 확인

### 앞으로의 작업 방법 (필수)
```bash
git checkout -b feat/T-XXX          # 1) feature 브랜치
# ... 작업 ...
git commit -m "feat(scope): 설명"
git push -u origin feat/T-XXX       # 2) 브랜치 push (main 직접 push는 차단됨)
# 3) GitHub에서 PR 생성 (또는 gh pr create)
# 4) Test 체크 통과 대기 → 머지 → 브랜치 삭제
```
> PR 생성 시 `.github/pull_request_template.md`의 체크리스트가 자동 표시됩니다.
> 이 워크플로는 **PR #1**(`chore: PR 템플릿 추가`)로 정상 동작 검증 완료.

## 8. 문제 발생 시 (트러블슈팅)

| 증상 | 확인/해결 |
|---|---|
| pytest가 CI에서만 실패 | 테스트 DB가 최신 마이그레이션(head)인지 확인 (`alembic upgrade head`). fresh DB 권장 |
| `ruff` 명령 없음 | `poetry install` (dev 의존성 포함) |
| `pnpm lint` eslint 없음 | 루트에서 `pnpm install` (eslint는 루트 devDependency) |
| main에 push 거부됨 | 정상 — 보호 정책. feature 브랜치 + PR로 진행 |
| Deploy가 빨간 X | `DEPLOY_ENABLED` 변수 미설정 시 skip이 정상. red면 5번 참조 |
