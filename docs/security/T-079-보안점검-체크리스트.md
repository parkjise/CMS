# T-079 보안 점검 체크리스트 (OWASP Top 10)

> **점검일:** 2026-07-11
> **대상:** apps/backend (FastAPI), apps/client (Next.js), apps/admin/superadmin
> **방식:** 코드 정적 감사 + 단위 테스트 검증
> **결과:** 통과 (실측 취약점 2건 발견 → 모두 수정)

## 1. 요약

| # | 점검 항목 | 결과 | 비고 |
|---|---|---|---|

**발견·수정한 실측 취약점 2건**
1. **저장형 XSS (JSON-LD)** — 공개 홈페이지의 `<script type="application/ld+json">`에 테넌트 편집 값(상호명·메타 설명·주소)이 미이스케이프로 주입되어 `</script>` 태그 탈출 가능 → `serializeJsonLd()`로 `<`,`>`,`&`,U+2028/2029 이스케이프 적용.
2. **JWT 서명 키 강도 미검증** — `APP_SECRET_KEY` 길이 제약이 없어 약한 키 사용 가능 → 기동 시 최소 32자 검증기 추가.

## 2. 항목별 상세

### 2.1 SQL Injection — ✅ 안전
- 모든 DB 접근은 SQLAlchemy 2.x ORM(`select()`, `insert()`) 사용 → 파라미터 바인딩.
- raw SQL은 RLS 컨텍스트 설정용 `text("SELECT set_config('app.current_tenant_id', :tid, true)")` 형태로, 사용자 입력은 **항상 바인드 파라미터(`:tid`)**로 전달. f-string/문자열 결합 SQL 없음.
- 근거: `app/db/session.py:set_rls_context`, `app/api/v1/endpoints/public.py`, `app/core/deps.py`.

### 2.2 XSS — ⚠️→✅ 수정
- **취약**: `apps/client/app/[tenant_slug]/page.tsx`가 `JSON.stringify(jsonLd)`를 `<script type="application/ld+json">`에 직접 주입. `jsonLd`는 `site.tenant.name`, `seo_settings.meta_description`, MAP 주소 등 **테넌트가 편집 가능한 값**을 포함. `JSON.stringify`는 `<`/`>`를 이스케이프하지 않으므로 `</script>` 삽입 시 태그 탈출 → 임의 스크립트 실행(방문자 대상 저장형 XSS).
- **수정**: `apps/client/lib/jsonLd.ts`에 `serializeJsonLd()` 추가 — `<`(`<`), `>`(`>`), `&`(`&`), 줄 구분자 U+2028/U+2029를 이스케이프. JSON 문자열 값 내부 치환이라 JSON 유효성 유지. `page.tsx`가 이를 사용하도록 변경.
- **CSS 변수 주입은 이미 안전**: `apps/client/lib/theme.ts:buildCssVarBody`가 값에 `[<>{};]` 포함 시 거부, 키 화이트리스트, 길이 120자 제한 → `<style>` 탈출 불가. (layout.tsx / preview/page.tsx 두 곳 모두 이 함수 사용)
- 회귀 방지: `__tests__/jsonLd.test.ts`에 `</script>` 페이로드 이스케이프 테스트 2건 추가.

### 2.3 CORS — ✅ 안전
- `app/main.py`: `allow_origins=settings.cors_origins`(명시적 화이트리스트), `allow_credentials=True`.
- 와일드카드(`*`) origin 미사용 → credentials와 결합 시 발생하는 취약 조합 없음.
- 근거: `app/core/config.py:cors_origins`(allowed_origins + admin/client URL).

### 2.4 JWT 시크릿 강도 — ⚠️→✅ 수정
- 알고리즘: HS256, 디코딩 시 `algorithms=[ALGORITHM]`로 고정 → **alg 혼동/`none` 공격 차단** (`app/core/security.py:decode_token`).
- **취약**: `APP_SECRET_KEY`에 길이 제약 없음(약한 키 허용 가능).
- **수정**: `app/core/config.py`에 `field_validator("app_secret_key")` 추가 — 32자 미만이면 기동 시 `ValidationError`. `.env.example` 기본값은 이미 32자 이상.
- 회귀 방지: `tests/test_config_security.py` 3건(미만 거부/32자 허용/초과 허용).

### 2.5 파일 업로드 검증 — ✅ 안전
- `app/services/image.py`: `Image.open().verify()`로 **magic-bytes 기반** 헤더 무결성 검증, 포맷 화이트리스트(`JPEG/PNG/WEBP/GIF`), 20MB 상한, 최대 1920px 리사이즈. 확장자·Content-Type 신뢰 없이 실제 디코딩으로 판정.
- 클라이언트 측(T-028 `packages/ui/ImageUpload`)에서도 타입·크기 1차 검증(방어적 다중화).

### 2.6 Rate Limiting — ✅ 안전
- slowapi 적용: 로그인 `10/minute`(`auth.py`), 결제 쓰기 `5/minute`(`billing.py`), 문의 접수(`inquiries.py`), AI 테넌트당 분당 한도(`config.ai_rate_limit_per_minute`).
- 전역 핸들러: `app/main.py`에서 `RateLimitExceeded` → 429 표준 응답.

### 2.7 RLS 테넌트 격리 — ✅ 안전
- 전 테넌트 테이블 `ENABLE ROW LEVEL SECURITY` + `FORCE`, `app.current_tenant_id` / `app.is_super_admin` 기반 정책.
- 요청마다 `get_db_with_rls`가 세션 컨텍스트 설정(`app/core/deps.py`).
- 격리 회귀 테스트 존재: `tests/test_rls.py`(테넌트 A→B 접근 403), `tests/test_public.py`.

## 4. 후속 권고 (T-079 범위 밖, 운영 배포 시)
- HSTS/보안 헤더, CSP는 Nginx 레벨(T-080)에서 적용 권장.
- 프로덕션 `APP_SECRET_KEY`는 32자 이상 + 고엔트로피 랜덤으로 교체(현재 검증기가 강제).
- reCAPTCHA(`recaptcha_secret_key`) 프로덕션 활성화로 문의/로그인 봇 차단 강화.
